## 0.4 我的边界（本场景 · 面试必答）

| 类型 | GIIC 15W 口径 |
|------|----------------|
| **负责** | GIIC **协议/网关**侧：per-connection、L1、Token Redis 异步批写；压测 **5000 msg/s + 96h** 验收闭环 |
| **协助** | 入口 **Nginx/sysctl**、**MySQL 生产档**与连接池对齐（`docs/ops`）；非 DBA/网工唯一 owner |

**一句防穿**：「5k 就挂是 **Sink/Redis 架构**，不是 32G 申请错了；**EventBus 那刀没上**是政策边界，靠网关侧卸压顶住。」

## Step 2 · 六算（⏱ 30s · 与 Step 1 合计 60s）

> 面试只报 **数量级 + 一条算式**；深挖用 §8 / 附录 A。

### 2.1 ① QPS

| 流 | 标记 | 结果 |
|----|------|------|
| 属性上报 | `[文档]` | **5,000 /s** |
| 反推周期 | `[反推]` | **30 s/台** |
| 心跳 | `[假设]` 60s/次 | **2,500 /s** |
| 每实例属性 | `[反推]` | **1,250 /s** |

### 2.2 ② 带宽

**输入** `[假设]`：5000 msg/s × **3 属性** × **1 KB**（scalability-plan §1.5）

```text
属性：5000 × 3 × 1024 × 8 / 10^6 ≈ 123 Mbps → 口播 ~120 Mbps
ACK：5000 × 200B × 8 / 10^6 ≈ 8 Mbps
心跳：设计表 ~24 Mbps
合计 ≈ 152 Mbps（万兆 ~1.5%）
```

### 2.3 ③ 存储（分 ES / buffer / MySQL / Redis）

**ES** `[假设]`：

```text
docs/s = 5000 × 3 = 15,000
日增 ≈ 15000 × 86400 × 0.5KB / 1024³ ≈ 619 GB/天/副本
```

**iot buffer** `[实测]`（10W case）：每 Pod **~30GB+**，合计 **~155GB** — ES 写不进时堆在应用侧。

**MySQL**：行级最新态；**16G BP** 盖热表 `[文档]`。

**Redis**：热路径优化前 **6 万+ QPS** `[文档]` → 目标 **<1000**。

### 2.4 ④ 缓存 / JVM

**连接内存** `[文档]` 逐项（37,500 连接/实例）：

| # | 对象 | ×37,500 | 小计 |
|---|------|---------|------|
| 1～7 | Netty/CoAP/PSK/Session/Operator… | ~11.8 KB/连接 | **~440 MB/实例** |

**堆** `[文档]`：密钥 Caffeine **~5.6G**；稳态 **8～10G**；申请 **-Xmx 32G**（≈3×）。

### 2.5 ⑤ 连接 / FD / 池

| 项 | 值 | 标记 |
|----|-----|------|
| TCP | 150,000 / **37,500**/实例 | `[文档]`/`[反推]` |
| Nginx 单 IP 硬顶 | ~64,000 | `[文档]` |
| MySQL max_connections | 1200；池 4×64≈256 | `[文档]` |

### 2.6 ⑥ 机器

**4 × (32C, 128G, SSD, 万兆)** + **148 Nginx** `[文档]`；压测 **5×30k 线程**。

**⚠️ 追问陷阱**

| 陷阱 | 标准答 |
|------|--------|
| 「1KB 哪量的？」 | **scalability-plan 带宽假设** `[假设]`；ES **不是** 1KB/doc |
| 「ES 全存整包？」 | **否**；**属性点** ~0.5KB/doc `[假设]` → **15000 docs/s** |
| 「440MB 怎么加？」 | **§2.4 表逐项**，~12KB×37500 |
| 「为何 5k 挂还要 32G？」 | 5k 挂 **Sink/Redis**；32G 按 **15W+Login+密钥** 申请 |

## §7 口播三档

### 7.1 电梯版（⏱ 30s）

> 15W **GIIC CoAP-TCP**，验收 **5000 属性 msg/s**，反推 **30 秒一台**。带宽按 **1KB×3 假设 ~120Mbps**；ES **按属性点 15000 docs/s**，磁盘粗算 **~620GB/天** 但要 **SSD**。连接 **~440MB/实例**，堆 **32G**（稳态 8～10G）。我负责 **网关协议段**，**device-manager 不能改**。

### 7.2 完整版（⏱ 90s · Demo 标准）

> 15W GIIC 我先 **Step 0**：**CoAP-TCP、15 万连接、5000 msg/s 验收** `[文档]`，**反推 30s/台** `[反推]`，不是 1W/s。
> **带宽**：历史按 **5000×3×1KB≈120Mbps**、加心跳 ACK **~152Mbps**，均为保守 `[假设]`；450B 仅是 `[文档/待补实测]`，抓包/脚本输出尚未补齐。
> **存储分三层**：ES **5000×3 docs/s**；单 doc **0.5KB、约620GB/天**是历史 `[假设]`，ES 增量实测未完成。10W NFS 写堵与 iot buffer 155GB 是另一条现场证据。
> **连接内存** 逐项 **~440MB/实例**；堆大头 **密钥 5.6G**，申请 **32G**。机器 **4×128G**，MySQL **16G BP**。
> **边界**：我负责 **网关/协议**；**EventBus 那刀没上**是 **device-manager 政策**；**~5k 挂**是 **Redis/Sink** 不是堆不够。

### 7.3 深挖版（⏱ 3min+ · 面试官咬住时）

1. **5000 推导**：150000÷30；Heartbeat JMeter **~85/s 合计**是日切片口径，与 **2500/s 设计心跳**不同 — 验收看 **Data T3**。
2. **440MB 展开**：§2.4 八项相加；队列峰值 **32×20KB** 最坏 **640KB/连接**（concatMap(1) 常态低）。
3. **32G vs 8G OOM**：15W 规划 **Caffeine 密钥+物模型**；v3 **5050 台 Operator 物模型 JSON 展开 5.7G Dominator** — 证明 **堆要按缓存模型估**。
4. **Redis 6 万→1 千**：Token/L1/Login 减负 + SCAN 替 KEYS；**禁改 connector** 后靠 **上游减负**。
5. **ES NFS 链**：write pool 满 + CPU 不高 → **等 IO** → buffer/dead 膨胀 → **换 SSD 治本**。
6. **入口 64k**：15W < 单 IP **~64000**；再高 **LVS/多入口**。
7. **MySQL 混部**：128G - 32G JVM - 8G OS ≈ **86G mysql_budget** → prod-128g 余量足。

## 附录 A · 公式速查卡（容量型通用）

```text
上报 QPS     = 设备数 / 上报周期(秒)                    [反推]
带宽(Mbps)   ≈ msg/s × 属性数 × 字节/属性 × 8 / 10^6   [假设→实测]
ES docs/s    ≈ msg/s × 每msg属性数                      [反推]
ES GB/天     ≈ docs/s × 86400 × avg_doc × (1+repl) / 1024³ × 1.3
连接MB/实例  ≈ Σ(单连接KB) × 连接数/实例 / 1024         [文档]
```

## 附录 B · 故障型步骤（与容量 Step 0→6 并列 · 不混步骤号）

```text
Step F0  现象（1 句 + 数字 + 时长）           ⏱ 20s

```

**10W ES NFS 实例**：现象 buffer **155GB** → 分层 ES write pool + NFS path → 根因 **等 IO** → 止血 replicas=0/refresh → 长期 **SSD**。

**5k OOM 实例**：现象 Old **96%** → jstat/jstack → MAT **operatorCache 5.7G** → 止血 dump/重启 → 长期 **缓存上限/物模型治理**。
