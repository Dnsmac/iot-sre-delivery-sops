# 02 设备影子与生命周期

> W1-D3 · 三行定稿（可背）

## 定义

设备影子（Device Shadow）指云端缓存的 **期望状态（desired）** vs **上报状态（reported）**；生命周期含注册、激活、在线、离线、注销等阶段。

## 现网有没有

**部分有 / 不完全叫「影子」。** 我们无 AWS 式 Shadow JSON；实际是 **配置字段 + 最新属性 + 会话三层**：TCP 会话在内存/H2、集群路由在 Redis（`connectionServerId`）、业务态在 MySQL。GIIC 生命周期：**注册码 → PSK 协商 → Login/Activate → Token（Redis）→ Heartbeat/Data → 断连重登**。

## 面试 30 秒

> 业界 Shadow 强调 desired/reported/delta。我们现网更偏配置加最新属性加会话路由：Redis 记 connectionServerId 找 Pod，内存/H2 管 TCP 会话。GIIC 我讲注册码、PSK、Login 发 Token、Refresh 续票、Heartbeat 保活；断连后 Token 失效要重新 Login，不能假设旧 PSK 永久有效。这和 OTA、属性下发共用同一条 messageSender 路由。

## 我们项目怎么做

### 1. 生命周期状态机（GIIC CoAP-TCP）

```text
[预注册]  API 生成注册码
    → Redis giic:registry:{devId}（productId + psk）
    → 可选预创建设备实例

[PSK 协商]  POST /.sys/psk
    → SecurityPskHandleServiceImpl
    → 读 registry 或 giicPsk 配置

[激活/登录]  /.sys/activate | /.sys/login
    → GiicAuthenticator 校验 secret
    → RedisGiicTokenStore 写 giic:token:{devId}
       （access / refresh / exp）

[业务期]  Heartbeat + Data
    → CoAPTCPServerDeviceGateway
    → DeviceGatewayHelper 创建 CoAPTCPDeviceSession
    → 写 connectionServerId / sessionId 到 DeviceOperator（集群 Redis）
    → DeviceOnlineMessage → EventBus → dev_device_instance.state=online

[离线]  TCP 断 / 心跳超时 / 主动 logout
    → sessionManager.remove()
    → DeviceOfflineMessage → state=offline
```

### 2. 「影子」在我们项目里对应什么

| Shadow 概念 | 我们实现 | 表/键 |
|-------------|----------|-------|
| reported（设备上报） | 属性上报 + `dev_firmware_info` + 可选 latest 表 | MySQL + ES |
| desired（云端期望） | 写属性 / 功能调用 / 设备配置 | `DeviceOperator.setConfig`、下行 DeviceMessage |
| delta（差异下发） | ❌ 无自动 diff | 每次显式发 writeProperty / functionInvoke |
| version | ❌ 无 Shadow version | 设备消息有 messageId / uid 去重 |
| 离线缓存指令 | ⚠️ 部分：下行失败记日志，无 Shadow 队列 | messageSender 需设备在线 |

**成熟方案理解（AWS IoT Shadow）**：

```json
{
  "state": {
    "desired": { "color": "red" },
    "reported": { "color": "green", "battery": 80 }
  },
  "metadata": { "desired": { "color": { "timestamp": ... } } },
  "version": 12
}
```

设备上线后云端推 delta，设备改 reported。我们 **没有这份 JSON**；等价做法是平台发 `WritePropertyMessage`，设备 ACK 后再上报属性，最新值落 MySQL/时序库。

### 3. 会话与集群路由（和生命周期绑定）

| 层 | 实现 | 说明 |
|----|------|------|
| 连接层 | `CoAPTCPDeviceSession` / `MqttConnectionSession` | 内存 + `./data/sessions/{clusterId}` H2 持久化 |
| 路由层 | `connectionServerId` in DeviceOperator Redis | 下行 messageSender 找持有会话的 Pod |
| 业务层 | `dev_device_instance.state` | online/offline，可能与 Redis 短暂不一致（重启残留） |

关键类：

- `PersistenceDeviceSessionManager` / `ClusterDeviceSessionManager`
- `DeviceGatewayHelper`（上线/离线编排）
- `GiicConnectionRouter` + `GiicConnectionState`（per-connection 队列）

### 4. MQTT vs GIIC 生命周期差异

| | MQTT | GIIC CoAP-TCP |
|--|------|---------------|
| 鉴权 | username/password 或证书 | PSK → Login Token |
| 保活 | MQTT keepalive + Will | `/.sys/heartbeat` |
| 离线原因 | `OfflineReason`（Will/超时/主动） | TCP 断 + 心跳超时 |
| Token | 通常无 | access/refresh 在 Redis，Refresh 续票 |

### 5. 级联场景的生命周期

- 下级设备状态经 Pulsar 同步到上级（`CascadeDeviceStateManagerImpl` 等）
- `dev_firmware_info` 可级联同步（`DevFirmwareInfoDataHandler`）
- 生命周期 **仍以本级会话为准**；上级看到的是同步态，不是直接持有 TCP

## 面试追问速答

**Q：有没有 Device Shadow？**  
A：没有 AWS 那种 desired/reported 文档；用配置 + 最新属性 + 显式下行指令替代，够用但语义不同。

**Q：设备离线时云端改配置怎么办？**  
A：改 DB 配置立即生效；**实时下发**需等设备上线，messageSender 路由到会话 Pod；无 Shadow 离线队列（MQTT 某些 SDK 有 persistent session，我们 GIIC 要重 Login）。

**Q：怎么知道设备在线？**  
A：`dev_device_instance.state` + `sessionManager.getSession(deviceId)` + Redis `connectionServerId`；GIIC 还有 heartbeat 续会话。

**Q：PSK 和 Token 区别？**  
A：PSK 是协商密钥（注册阶段）；Token 是 Login 后的业务票据，存 Redis，Refresh 续期。

## 诚实边界

- **做过**：GIIC Login/Token/Heartbeat 链路、会话路由、15 万连接压测
