## 一、L4 是什么（先对齐「深挖」的刻度）

面试官的追问通常走这条路：**问概念 → 问原理 → 问你怎么定位 → 问你怎么权衡**。对应四级：

| 级 | 含义 | 口述要求 | 例子（以「OOM」为例） |
|----|------|----------|----------------------|
| **L1** 概念 | 一句话说得清 | 20s 报结论 | "operatorCache 无界缓存把堆吃满了" |
| **L2** 原理 | 讲得清机制 | 30s 讲机制 | "无 maximumSize/TTL，注销不 invalidate，物模型永驻" |
| **L3** 定位 | 会自己排查 | 40s 报命令+数字 | "jstat Old 96% → dump → MAT Dominator 5.66GiB 占 78%" |
| **L4** 权衡 | 接得住连环追问 | 60~90s 反客为主 | "`-Xmx8G` OOM 事故说明无界缓存不能靠扩堆根治；32G 只属于 GIIC 15W 容量规划，两条线只能作方法论对照" |

**验收口径**：简历主炮（IoT 压测/OOM/ES/级联）必须到 **L4**；ERP/MySQL/Redis/JVM 只在真实用过的点上冲 L4，没有证据的题明确降级为通用机制。

## 二、简历暴露面 → 必问清单（反推）

你简历每句话都是一个钩子，面试官顺着就能追。把钩子收敛成 7 个必问维度：

| 必问维度 | 简历钩子（面试官从哪句起问） | 具体必问题 |
|----------|------------------------------|-----------|
| **业务场景** | "IoT Meta 平台 / 15 万压测 / 20W级联历史材料" | 设备接入架构怎么设计？15W 要几台机器？20W级联为何当前不主讲？ |
| **并发** | "改连接模型（队列）" | 背压怎么做的？队列满了怎么办？线程池/锁在项目里怎么用？ |
| **MySQL** | "MySQL 三主 `[画像]` / 批量落库 `[待补证]` / 慢 SQL `[通用机制]`" | 索引/事务/MVCC/锁；Login 写放大和深分页在无证据前只按通用题防守 |
| **MQ** | "Pulsar 集群 / 级联" | 消息不丢/不重/顺序/积压；设备上报走 Pulsar 吗？ |
| **性能** | "线上 OOM 及 BUG 排查" | 接口慢怎么定位？CPU 高怎么查？资源不高但慢？ |
| **压测** | "15W GIIC / 20W MQTT假设题 / 20W级联待核对 / 10W ES" | 先分证据态，再答指标、验证与角色边界 |
| **优化** | "改连接模型 / Caffeine / Nginx" | 优化前拿 baseline 吗？每次动一层还是全改？怎么回归？ |

> **红线**（说了就扣分，背下来）：① 不把 15W 吹成 40W；② 不说「上报走 Pulsar」；③ 不说「独立 EMQX Broker」；④ 20W MQTT 是官方/假设迁移题，明确没做过；⑤ OpenAPI 不编造 100 TPS。

## 三、7 维 gap 分析（现状 → L4 → 缺口 → 动作）

| 必问维度 | 现有资料 | 当前深度 | 到 L4 缺什么 | 补的动作 |
|----------|----------|----------|--------------|----------|
| **业务场景** | IoT 主链路、GIIC、ERP 边界 | L3→L4 | 需要持续口述串联 | ✅ 新增 [面试连环深追脚本](面试连环深追脚本.md) |
| **并发** | GIIC 有界队列、水位保护 | L3→L4 | `queue-size=32` 来源只能按复盘口径讲 | ✅ 已补连追和边界 |
| **MySQL** | ERP 幂等、唯一约束、状态机 | L2→L3 | 具体表结构、SQL、慢 SQL/死锁事故、收益待补证 | 先讲真实机制，不编实战事故 |
| **MQ** | EventBus 主链路、Pulsar 级联/跨服务 | L3→L4 | Pulsar 具体分区数、积压处置证据需补 | ✅ 已修正第一跳边界 |
| **性能** | ES NFS 写慢、155GB buffer | L3→L4 | 修复后收益和完整时间线待补证 | 先按分层排查讲 |
| **压测** | GIIC 15W、5000 msg/s、96h | L4 主炮 | 40W 仅背景；20W MQTT 非经历 | 每天练六算 |
| **优化** | operatorCache OOM | L4 主炮 | 修复后命中率/回源成本待补证 | 讲有界缓存与代价 |

**真实完成度结论**：七维都有可用入口，但不是七维全部 L4。当前可主打 L4 的是压测、OOM 优化、ES 性能排查、IoT/MQ 边界；MySQL/Redis/ERP 先按“真实锚点 + 通用机制 + 待补证”防守。

**OOM/容量红线**：`-Xmx8G`、约 5050 台、Dominator 约 5.7G/78% 是 operatorCache OOM 事故线；32G 是 GIIC 15W 容量规划线。两者只能用于说明“容量估算不能替代有界治理”的方法论对照，不能写成同一次事故。
