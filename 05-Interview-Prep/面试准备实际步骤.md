## 一、面试前准备（面试前1周）

### 步骤1：准备自我介绍（30分钟）
**做什么**：准备30秒自我介绍
**怎么做**：
1. 打开记事本，写以下内容：
   ```
   我做了11年Java，前面在社区、电商做过后端和高并发模块；
   2025年起在物联网平台，主要改iot-server，对接K8s上约30个服务和中间件。
   最近负责GIIC（CoAP-TCP）15万级长连接压测优化，连续长稳跑过4×24小时。
   求职资深Java后端·IoT平台，深圳25K左右。
   ```
2. 背诵3遍，直到能流畅说出
3. 录音检查，确保没有卡顿

**验证**：能流畅说出30秒自我介绍，没有卡顿

### 步骤2：准备90秒全链路（1小时）
**做什么**：准备90秒IoT全链路口述
**怎么做**：
1. 打开口述稿文件：`05-Interview-Prep/口述稿/W1-全链路.md`
2. 背诵以下内容：
   ```
   设备通过MQTT TCP 1883连到我们MetalLB VIP，由iot-web的nginx做TCP透传，
   进到iot-server Pod里内嵌的MqttServer——JVM线程在Pod里监听1883，不是独立EMQX Broker。
   
   连接时用clientId当设备ID，从MySQL拿产品和密钥做认证。
   真正干活的MQTT TCP长连接在Pod内存里的localSessions；
   同时往Redis写connectionServerId做集群路由，还可选落H2存元数据——Pod重启TCP还是要设备重连。
   
   设备PUBLISH之后，先进iot-server内置MQTT解码，再经DeviceMessageConnector发到EventBus——不是先进Pulsar。
   持久化：ES时序、MySQL最新值和在线状态（批量缓冲写）、Redis限流和路由；级联等场景会用到Pulsar。
   
   下行时，API打到没有该设备会话的Pod，会查Redis的connectionServerId，经集群RPC转到持有TCP的那台，再MQTT下发。
   
   我日常改最多的是iot-server。压测方面：最近负责GIIC（CoAP-TCP）15万级长连接优化——
   按连接拆队列、L1、Token Redis、异步批写；并协助入口Nginx/内核临时端口与MySQL生产档；
   device-manager政策不能改，EventBus那刀没上。连续长稳跑过4×24h（96h）；平台整体方案不是owner。
   级联/Pulsar是另一条线，被追问再讲。
   ```
3. 背诵5遍，直到能流畅说出
4. 录音检查，确保没有卡顿

**验证**：能流畅说出90秒全链路，没有卡顿
