## T1 · 3000 个数找最大 K 个（堆）

- **一句话**：维护 **大小为 K 的小根堆**，扫一遍数组，比堆顶大就替换，最后堆内就是 TopK。
- **复杂度**：时间 **O(n log K)**，空间 **O(K)**；K 远小于 n 时比全排序 O(n log n) 划算。
- **展开**：建堆从 `len/2-1` 非叶子节点下沉；若求最小 K 个用大根堆。数据量小用插入排序；基本有序用插入/冒泡；随机大数据用快排/堆/归并。
- **追问**：「K 很大呢？」→ K 接近 n 直接堆排序或快排更省事。「流式数据呢？」→ 固定大小堆，内存 O(K) 不变。
- **分级**：了解级算法题。可以说“控规模思想类似”，但不说项目里用堆解决过 Login 风暴。

## T2 · 文件不重复整数排序（位图 / 外部排序）

- **一句话**：整数 ≤7 位（0～9,999,999），用 **位图 1MB 级** 标记存在，扫位图按序输出；超内存则 **分块排序 + 多路归并**。
- **数字**：7 位整数范围 10^7 bit ≈ **1.25MB** 位图 `[反推]`。
- **展开**：位图适合 **稠密、范围已知**；稀疏用 **分段位图**（有数据才分配段）。外部排序：切块入内存排序写临时文件，最后 **小根堆多路归并**。
- **追问**：「负数/字符串呢？」→ 位图不行，改哈希分桶或基数排序。「磁盘 IO 怎么减？」→ 归并时控制 fan-in、顺序读、缓冲区对齐。
- **分级**：中绑定。设备 ID/连接去重可以类比，但现网具体是否使用 Redis Set 分段 + TTL 待补证，不能当真实项目口径。

## T3 · 亿级日志 Top10 热词（MapReduce）

- **一句话**：**Map** 分片统计 `(word,1)` → **Shuffle** 按 word 分区 → **Reduce** 聚合计数 → 全局 **小顶堆保 Top10**。
- **展开**：单机装不下全量词频，必须分布式；Combiner 在 Map 端预聚合减网络。TopK 全局只需维护 10 个元素的小堆，内存恒定。
- **追问**：「热点 key 倾斜？」→ 加盐打散 + 两阶段聚合；或采样近似 TopK。「实时呢？」→ Flink 窗口 + 增量 TopK。
- **分级**：了解级大数据题。ES NFS 可作为“分层定位”类比，不说做过 MapReduce 热词统计。

## T4 · 两个 50 亿 URL 找相同（哈希分桶）

- **一句话**：两文件分别 **hash(url) % N 分桶** 落盘，同桶内内存 **HashSet 求交**；URL 长可用 **前缀树** 但内存要控。
- **数字**：50 亿条若每桶 5000 万，要 **1000 桶** 量级才压得进单机内存 `[假设]`。
- **展开**：分桶键要均匀；桶仍太大则 **二次哈希**。和 MapReduce 本质是同一模式：先分区降规模，再局部精确算。
- **追问**：「URL 很长内存爆？」→ 桶内只存 hash 值求交，最后回表校验原串防碰撞。
- **分级**：了解级算法题。只保留“分桶降规模”的通用思想，不硬钩 GIIC 具体实现。

## T5 · 海量数据找中位数（二进制分治）

- **一句话**：按二进制位从高位到低位 **0/1 分桶计数**，选累计超过总数一半的那一侧递归，类似 **QuickSelect 的位图版**。
- **复杂度**：32 位整数约 **32 轮**，每轮 O(n) 扫盘 `[反推]`。
- **追问**：「内存不够一次扫？」→ 外排分块只传计数，不传全量。 「浮点数呢？」→ 离散化或近似算法（T-Digest）。
- **分级**：了解级算法题。可以用 15W÷30s=5000 msg/s 说明“先估数量级”，但不说中位数算法用于项目。

## T6 · 秒杀系统（超卖 / 少卖）· 强绑定变体

- **真实项目先开口**：我真实做过的不是秒杀大促，而是 ERP 300+ 商户、日峰值约 3000 万下的并发正确性：分布式锁、幂等、唯一约束、状态机。
- **官方变体一句话**：秒杀标准方案是 **Redis 预扣库存（Lua 原子 DECR）** → 成功发 **MQ** → 订单服务异步落库；消费端 **幂等 + 唯一约束** 防重。
- **展开**：
  - **超卖**：判断+扣减必须原子（Lua / 单线程 Redis）；DB 最终扣减用乐观锁或 `UPDATE stock WHERE stock>0`。
  - **少卖**：MQ 发送失败要 **重试 + 死信 + 补偿扫描**（对账 Redis 与 DB 库存差）。
  - **架构**：CDN 静态、网关限流、队列削峰、热点 key 拆分。
- **追问**：「Redis 挂了？」→ 降级关闭秒杀 / 本地令牌桶限流；「热点商品？」→ 库存分片 key + 异步合并。
- **反抛**：如果您要听真实项目，我讲 ERP 幂等、唯一约束和状态机；如果您要听秒杀，我按官方变体展开 Redis Lua、MQ 和补偿。
- **边界**：不说做过秒杀库存分片、Lua 扣库存或大促压测；ERP 表结构、事故、收益待本人补证。

## T7 · 40 亿 QQ 号去重（位图 / 布隆）

- **一句话**：QQ 号可映射整数则用 **分段位图**；内存仍不够就 **分桶 + 桶内位图**；允许误判用 **布隆过滤器** 做第一层。
- **数字**：40 亿 bit ≈ **500MB** 量级裸位图 `[反推]`，通常要分段或分布式。
- **追问**：「布隆误判？」→ 只有「可能存在」假阳性，不存在一定不存在；要精确第二遍用 Set 校验。
- **分级**：中绑定。设备注册去重、clientId 冲突检测可类比“存在性判断”，具体实现待现网证据补齐。

## T8 · 密码传输与存储

- **一句话**：传输 **HTTPS/TLS**；存储 **盐 + 慢哈希（bcrypt/Argon2）**，只存摘要不存明文；防暴力 **限流 + 锁定**（Redis 记 IP/用户失败次数）。
- **展开**：慢哈希防彩虹表；盐 per-user 防批量撞库；登录失败锁定一般 **限 IP**（防误伤共用账号）。
- **追问**：「怎么重置密码？」→ 一次性 token + 短过期 + 用后作废。「设备认证呢？」→ IoT 认证可以按“设备标识 + 密钥/证书 + 服务端校验”通用原则回答。
- **边界**：唯一索引未证明具体认证数据来源、密钥存储形态或日志脱敏实现，本题只讲安全原则，不作为项目实战钩子。

## T9 · 推荐系统（召回 + 精排）· 了解级

- **一句话**：**召回**（多路粗筛：协同/内容/热门，各取 Top-N）→ **精排**（模型打分排序）→ **重排**（多样性/去重/业务规则）。
- **展开**：粗筛要 **快且广**（向量/倒排/聚类中心）；精筛要 **准但贵**（特征交叉、深度模型）；离线训练 + 在线特征服务分离。
- **追问**：「冷启动？」→ 热门 + 类目偏好 + 探索流量。「实时性？」→ 近线特征（Flink）+ 分钟级模型更新。
- **边界**：IoT 里没有推荐生产经验，本题只到了解级；不要把 EventBus 扇出硬说成推荐系统经验。

## T10 · 广告系统（架构 + 业务）· 了解级

- **一句话**：**投放服务** 读用户画像 + 广告排期 → **竞价/优先级选广告** → 展示埋点 → **Kafka 异步入仓** 算 CTR/转化。
- **架构层**：LB → 投放服务 / 画像服务 / 监测服务；**MySQL 元数据 + Redis 热数据 + MQ 异步**。
- **业务层**：频控（用户维度曝光上限）、排期、点击去重、反作弊（设备指纹）。
- **追问**：「高 QPS 读画像？」→ 本地缓存 + Redis + 异步刷新；「一致性？」→ 展示以投放时刻快照为准，统计最终一致。
- **边界**：没有广告投放生产经验，本题只讲通用架构；设备影子/最新态只能做最终一致模型类比。

## T11 · 分布式 KV · 一致性哈希 · 强绑定变体

- **一句话**：节点和 key 都 hash 到 **2^32 环**，key 顺时针找第一个节点；**加虚拟节点** 解决分布不均；扩缩容只影响相邻段。
- **展开**：普通取模 `hash%N` 在 N 变化时 **几乎全部迁移**；一致性哈希只迁移 **K/N** 量级数据。Redis Cluster / Memcached 客户端分片都基于此思想。
- **追问**：「数据倾斜？」→ 虚拟节点数拉高（如 150 vnode/物理机）。「和 Redis 槽位关系？」→ Redis 16384 slot 是固定分片表，思想类似但实现更工程化。
- **真实项目先开口**：IoT 下行要先找到设备连接在哪个实例，会话路由属于真实锚点；一致性哈希是“key 找节点”的官方变体。
- **边界**：可以讲会话路由思想，不编造现网用了 2^32 hash 环、虚拟节点或 Redis Cluster slot 迁移方案。
