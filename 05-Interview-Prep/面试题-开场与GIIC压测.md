## 一、面试怎么开（按场景选 1 段）

### 1. HR / 自我介绍 · 30 秒（先背这个）

> 我做了 **11 年 Java**，前面在社区、电商做过后端和高并发模块；**2025** 年起在物联网平台，主要改 **iot-server**，对接 K8s 上约 30 个服务和中间件。最近负责 **GIIC（CoAP-TCP）15 万级**长连接压测优化，连续长稳跑过 **4×24 小时**。求职 **资深 Java 后端 · IoT 平台**，深圳 **25K 左右**。

**禁止**：一开口讲 MetalLB/CNI；把 15W 说成 40W；说「主导全场压测」。

### 2. 技术面 · 90 秒主开场（链路）

背 [`口述稿/W1-全链路.md`](口述稿/W1-全链路.md)。顺序固定：

```text
设备谁连 → 上报走哪（EventBus，不是 Pulsar）→ 会话/下行 → 我改什么 → 压测一句
```

压测收尾用下面 **15 秒**，替换旧「只协助 40W Pulsar」口径。

### 3. 技术面 · 压测 30 秒（被问「做过压测吗」）

> 我们有一条 **GIIC CoAP-TCP** 接入。目标 **15 万在线**，5 台压测机各 3 万线程。优化前大概 **5 千**就 Login 超时、Sink 断流，中期卡在约 **14 万**。我负责协议/网关侧：连接模型拆成 per-connection、L1 热缓存、Token 改 Redis、Login 写路径减负。现在 **15 万能稳住**，连续长稳已经 **96 小时（4×24h）**，超过我们内部 **72h** 验收节点。平台整体方案我不是 owner，这段链路的改造和验收闭环是我负责的。

### 4. 开场顺序（对标学习路径 §二）

### B. IoT 链路（技术面开场后必追）

| # | 问题 | 答法要点 | 别踩坑 |
|---|------|----------|--------|
| B1 | 设备连谁 | VIP:1883 → nginx 透传 → **内嵌 MqttServer** | 不是独立 EMQX |
| B2 | 上报走 Pulsar 吗 | **否**；解码 → **EventBus** → ES/MySQL | 旧口径已废 |
| B3 | Pulsar 干什么 | **级联**等异步；与接入两条线 | 别和 MQTT 混 |
| B4 | 多副本怎么下行 | Redis `connectionServerId` → 集群 RPC → 持会话 Pod | |
| B5 | Pod 重启怎样 | TCP 断，设备重连；路由靠 Redis | |

### C. GIIC / 压测（有证据，优先练）

| # | 问题 | 答法要点 |
|---|------|----------|
| C1 | 压测规模多大 | **15 万在线**；5×3 万线程；约 4 节点 |
| C2 | 你具体做了什么 | 连接模型 / L1 / Token→Redis / Login 写放大；**段负责** |
| C3 | 优化前什么现象 | ~5k Login/Sink 挂；中期卡 ~14.3W |
| C4 | 怎么证明好了 | 15W 可维持；长稳 **≥96h（4×24h）**；目标 7D |
| C5 | 为什么卡 14 万 | Login 热路径写 configuration → DB/连接池；后迁 Redis |
| C6 | L1 缓存会不会脏读 | miss/不匹配 **回 Registry/Redis**；跨节点不靠纯本地 |
| C7 | 压测配置和生产一样吗 | r2 后 **一套配置**（压测=上线） |
| C8 | 你是压测负责人吗 | **不是全场 owner**；负责 GIIC 协议/网关改造与验收闭环 |
| C9 | CoAP 和 MQTT 什么关系 | 平台多协议；**主讲仍 MQTT**；GIIC 是 CoAP-TCP 一条线 |
| C10 | 还有 40 万吗 | 平台规模背景/另线；**主数字用 15W**，不把 15W 吹成 40W |

### D. Java / 高并发（卖 5 年+ 信用）

| # | 问题 | 答法要点 |
|---|------|----------|
| D1 | 热路径为什么不能 `.block()` | 压测下拖死事件线程；PSK 等已改 reactive |

| D4 | 电商/社区代表作 | 故事 #1（W7 前须定稿，现在可一句带过） |

### E. K8s / 中间件（防守，不当开场）
