## 各版怎么改的

**01 后端平台 Java（主攻）**
- 定位标签回到「核心服务 · 压测优化 · 稳定性 · 信创交付」；头图强调 11 年 Java + IoT + ERP 带队（业务价值）。
- 技能区补一条「专业与团队」；IoT 项目按后端视角排序，保留深 Java/中间件/OOM 案例。
- GIIC 压测按你草稿口径改为「负责网关连接模型与协议热路径」——这是你真负责的部分，不算越界。

**02 IoT 云原生 / 交付（次攻）**
- 方向改为「交付 / 云原生」而非「大厂核心 SRE」（守红线 C 类不投）。
- 头图与技能前置 K8s、麒麟信创、可观测、压测容量；IoT 项目把「麒麟完全离线交付」「10 万级存储/中间件排障」「反亲和/HPA」提前。
- 监控按「部署 / 使用者」表述（Prometheus/Grafana/Loki、建立告警规则），不写「自研监控平台」。

**03 AI 基础设施（模板 / 转型）**
- 把已有的「大规模实时数据链路 + 可观测」作为 AI 数据底座来讲——这是你真实可讲的部分。
- AI 技能标为「学习 / 构建中」，AI 项目标为「个人项目 · 构建中」，并带**内部提示**（打印时自动隐藏）。
- **投递前必须**：跑通 AI 运维助手、能讲清 RAG/向量库/vLLM/Agent/MCP 的取舍，并把「学习中 / 构建中」改成可核实描述。未做到不要投，否则技术面会崩。

## 红线（三版通用，均未触碰）

- 压测只用「协助 / 参与」/「负责网关连接模型」，**未写主导/负责人**；40 万级(参与)未引入（避免过度声明，与 v2 口径一致）。
- 无「空窗」，2023—2025.1 远程按既有「技术服务合作」口径，不在简历写主体。
- 监控按「使用者 / 部署者」表述；信创按「麒麟 V10（国产 Linux）」而非「鲲鹏」表述。
- 教育、时间线、联系方式均沿用原稿，未改。

## 导出 PDF（三版均同）

在项目根或任意目录执行（Chrome 已确认在 `C:\Program Files\Google\Chrome\Application\chrome.exe`）：

```powershell
$base = "D:\project\iot-sre-delivery-sops\05-Interview-Prep\resume\三版"
$cases = @(
  @{ h="$base\01-后端平台Java\骆峰-资深Java后端IoT-主攻.html"; p="$base\01-后端平台Java\骆峰-资深Java后端IoT-主攻.pdf" },
  @{ h="$base\02-云原生交付\骆峰-IoT云原生交付.html"; p="$base\02-云原生交付\骆峰-IoT云原生交付.pdf" },
  @{ h="$base\03-AI基础设施\骆峰-IoT-AI基础设施.html"; p="$base\03-AI基础设施\骆峰-IoT-AI基础设施.pdf" }
)
foreach ($c in $cases) {
  $uri = "file:///" + ($c.h -replace "\\", "/")
  & "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf="$($c.p)" "$uri"
}
```
