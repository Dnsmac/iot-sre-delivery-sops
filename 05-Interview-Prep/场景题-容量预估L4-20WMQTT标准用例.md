## Step 1 · 业务输入

### 1.1 题目输入 `[假设]`

| 项 | 值 |
|----|-----|
| 在线 TCP | **200,000** `[假设]` |
| 上报周期 | **60 s/台** `[假设]` |
| 单节点连接上限 | **50,000** `[假设]`，不能当现网硬上限 |
| JVM 堆（仅作候选起点） | **32 GB/实例** `[假设]`，必须压测校准 |

### 1.2 反推 `[反推]`

```text
上报 QPS = 200,000 / 60 ≈ 3,333 msg/s
每实例连接 = 200,000 / 4 = 50,000（占 50k 上限的 100% → 顶格，需 +1 节点）
```

## Step 4 · 条件 + 余量（⏱ 30s）

| 项 | 结论 |
|----|------|
| 连接/节点 | 若实测上限为 50,000，则 4 节点无余量，可把 +1 节点作为候选方案 |
| ES | **本地 SSD**；忌 NFS（10W 案例已证写不进） |
| 瓶颈 | 先验证连接、堆、ES、DB 各层水位，不能预设一定转到 ES/Pulsar |
| 余量 | 5 节点与 32G 只是候选容量档，须以基线和拐点校准 |
