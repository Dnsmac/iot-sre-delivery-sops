
## [09:25] atomic-center-server NotReady 判读
- Kuboard 截图：Pod cnmb2 年龄 14 分钟、NotReady、探针失败时间 09:06:31 = 调度/初始化时刻 → 从创建起就没 Ready 过。
- 判定：14 分钟只是存活时长非故障；根因链仍是 broker SIGSEGV 循环 → Spring Pulsar subscribe 超时 → 启动卡死 → readiness 永远不过。重启 atomic-center 无意义。
- 待确认：broker 是否已加 managedLedgerDigestType=CRC32 并生效；atomic-center 容器内存 1136MB 偏高需留意。

## [09:45] 坐实节点时钟漂移十几分钟
- 容器内 date 与真实时间差十几分钟 → 宿主机（节点）系统时钟不准，K8s 不需要装 NTP，修在宿主机 OS 层。
- 已给方案：timedatectl/chronyc 检查 → systemctl enable --now chronyd；内网无 NTP 源则指向内网源（AD 域控/ESXi）或 timedatectl set-time 手动校时。
- 风险提示已给：时钟漂移十几分钟还会引发 Pulsar JWT/TLS 证书校验、ZK 会话等次生问题，所有节点都要对齐。

## [10:00] 本机 x86 上传前验证 pulsar-all:4.0.13
- 关键风险：x86 本机 docker pull 默认拉 amd64 → 上传到 arm64 服务器直接白干。必须 docker pull --platform linux/arm64 并 inspect 确认 linux/arm64。
- 基座/版本可本机验证：Docker Desktop 自带 QEMU 模拟，x86 可跑 arm64 容器执行 cat /etc/os-release、ldd --version、cat /pulsar/VERSION。
- SIGSEGV 冒烟测试无法本机做（QEMU 模拟测不出原生崩溃），必须上服务器后 standalone 实测。
