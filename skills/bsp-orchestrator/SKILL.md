# BSP Orchestrator（唯一入口）

> 配合 `~/.cursor/commands/bsp.md`。  
> **目标**：用户给出需求后，不再重复出现——浅读大仓、忽略定时/补偿、文档矛盾、改 A 坏 B、热路径乱写库、未批准就编码。  
> **用户不必回忆机制**：Agent 在 L4 主动扫齐并联路径并输出机制清单表；用户只提供现象、验收、边界。  
> **运行默认（不可忘）**：生产 **高并发、多实例、Reactive、突发流量**；除非用户明示单实例/压测，**一律按最坏情况**评估方案与复盘。

**开场声明（回复第一行必写）**：`[BSP] 已 Read bsp-orchestrator，Gate 0 起执行。`

> **规则原则（防越写越松）**：编码相关约束 **只认下面「编码硬门禁 6 条」**；禁止再散增 Gate 5.x。用户 **不必** 在 L0 重复关键词——Agent **默认**执行 #2～#6。

## 编码硬门禁（6 条 — 违反即停，优先级高于 Gate 5 细节）

**编码前**（Agent 自检，不对用户展示；任一条不过 → **不得 Write**）：

| # | 门禁 | 默认行为（用户不必记） |
|---|------|------------------------|
| **1** | **授权** | 须能原文引用 `批准修复` / L0 `零确认` / `批准段 N`；**具体改法、`/buc`/`/bsp`、Agent 自说「已执行」均无效**（见「无效批准」表） |
| **2** | **范围** | 交付包 **必写「只改」**（文件/类/方法）；**禁止碰**（Agent 推断：删数据、清全量缓存、改生产默认 yaml、无关 refactor） |
| **3** | **删写** | diff 若含 `delete`/`remove`/`invalidate`/物理删/逻辑删/批量改态 → 交付包 **必附「删写对照表」**（触发条件｜删谁｜**不应删谁**｜回滚） |

**编码后**（缺任一条 → **不得称 Phase A 完成 / 不得合 Gerrit**）：

| # | 门禁 | 默认行为 |
|---|------|----------|
| **4** | **diff 对账** | `git diff` 每个改动文件 **∈ 交付包「只改」**；多出的文件/ hunk → **P0 整段 revert**，不得「顺手优化」 |
| **5** | **编译** | **禁止任何 `mvn`**；摘要只给 **IDEA 编译清单**（KhLinks 链见 Gate 5 附录） |
| **6** | **验收诚实** | **禁止新增** `*Test.java`（L0 写「要单元测试」除外）；T7 **必附「未覆盖场景」≥1 条**（Agent 填：本地缺哪类数据/环境，合入后仍可能炸什么） |

**BUC Phase B**：#4 多出改动、#3 无删写表、#6 未写未覆盖 → **P0/P1**，不得通过。

## 交付模式（用户只关心结果时用）

**直通修复（BUG 默认）** — 见下 **「授权红线」**；交付包 → **等用户一条显式批准** → 同会话编码。

| 模式 | 何时 | 用户要做什么 | Agent 要做什么 |
|------|------|-------------|---------------|
| **直通修复（默认）** | `/bsp` + BUG，L0 **未**写零确认 | **1 次显式批准**（见红线） | 首轮仅 **交付包 + 停**；下一条收到批准后才编码 |
| **零确认** | L0 **同条消息**含 `直接修`/`不用再确认`/`零确认` | **0 次** | 首轮交付包 + 同会话编码（**不得**再索要批准） |
| **分段模式** | L0 含「分段」或高风险 | 每段 `批准段 N` | 见 Gate 3 |

**用户不必回答的过程题**：机制清单、定时任务、cap、业务影响 — Agent **内部做完**，写入交付包与 `docs/`（**授权后**落盘），不在聊天里拆成十几次问答。

**仅阻塞才问**（**最多 1 个**阻塞问题，问完 **必须停** 等批准）：缺环境/账号、破坏性操作未授权、两方案业务后果相反且 L0 未限定。

**高风险自动升分段**（须告知原因，**不得**一次 `批准修复` 全做）：热路径新增 DB 写、跨模块 >3 文件、架构/协议变更。

**Gate 3 自动升分段（v2，BUG 默认强制评估）** — 命中 **任一条** 须在交付包标 **「建议分段」** 并给出 PR1/PR2 边界；用户仍坚持一次合入须 L0 写 **`不分段`**：

| 触发条件 | 典型分段 |
|----------|----------|
| 改动 **>3 文件** 且 **跨 2+ Maven 模块**（如 `device-manager` + `open-api-server`） | PR1 对外路径 / PR2 缓存或内部 |
| **换调用路径**（HTTP↔gRPC、进程内 dispatch、去掉 hop） | PR1 行为 parity + 开关；PR2 性能优化 |
| 同时动 **默认 yaml 开关/TTL** 与 **业务逻辑** | PR1 逻辑（生产默认不变）；PR2 压测 profile |
| 热路径新增 DB 写 或 架构/协议变更 | 按影响面拆段 |

## 授权红线（**坚决杜绝**，优先级高于一切便利）

### 未授权前 **禁止**

| 禁止项 | 说明 |
|--------|------|
| 改业务代码/配置/迁移/SQL | 含「先改一点试试」「顺手修 nearby」 |
| **自批自改** | 禁止「默认批准」「我先按推荐实现」「你应该同意了」 |
| 用推断代替批准 | 用户描述现象、选 A/B/C、批评流程、问「有没有问题」**均不算**批准 |
| **具体改法 ≠ 批准** | L0 含 commit/类名/「把 A 改成 B」/「恢复成读 X」/打 **`/buc` 或 `/bsp`** → **仍须**下一条 **`批准修复`**（除非同条 **`零确认`/`直接修`**） |
| **同轮交付+编码** | 未批准时在 **同一回复** 输出 diff、写 hotfix §已修复、标题 **「交付包（已执行）」** |
| 模糊肯定 | 单独「好的/行/继续/OK」**不算**；须同句含 **`批准修复`** / **`批准运维`** / **`按推荐修`** |
| 十几次来回仍编码 | 多轮讨论后 **仍未收到批准词 → 继续禁止编码**，不得某轮突然开改 |
| 旧会话批准 | 新 BUG / 新 `/bsp` **须重新批准**（除非 L0 零确认词仍在同条需求内） |
| 代用户批 | 禁止替用户勾选 Gate、禁止写「已视为批准段 1」 |
| **Agent 跑 Maven** | **禁止** Agent 执行任何 `mvn`（含单模块 `compile`、`-DskipTests`、`test`、`verify`、`install`）；编码后只输出 **IDEA 编译清单**（见 Gate 5.1）；用户**明确要求**「帮我跑 mvn …」除外 |

**未授权前允许**：只读排查、交付包、文档 **检索**；专项 md **最多**写「待批准」草案（**禁止**写 §变更/§已修复）。

### 合法授权（三分法 + 分段，须能在对话中 **原文引用**）

| 类型 | 合法触发 | 允许动作 | 无效示例 |
|------|----------|----------|----------|
| **授权查询** | 同条或单独消息含：`授权查询` / `授权你查询` / `授权查 ES` / 给出 ES/DB **只读**账号密码 | **立即** curl/SQL 只读诊断；**不等** `批准修复` | 把「授权查询」当成代码批准 |
| **批准运维** | 单独消息含：`批准运维` / `授权执行恢复` / `批准执行恢复` | ES **删索引、reindex、改 alias** 等破坏性运维；**须先**写备份步骤再执行 | 「帮我恢复」无「批准/授权执行」→ **只出 SOP，不执行** |
| **批准修复** | **单独一条用户消息**含：`批准修复` / `按推荐修` / `批准段 N` | 改 **业务** Java/yaml/迁移/SQL + Gate 4 落盘 | 见下 **「无效批准（一律驳回）」** |
| **零确认（代码）** | **仅** `/bsp` 或 `/buc` **同条**「我的需求」含：`直接修` / `不用再确认` / `零确认` | 首轮交付包 + **同会话编码** | 第 5 轮说「那直接修吧」而首条 L0 无零确认词 → **仍须** `批准修复` |
| **零确认（只读定位）** | 同条含：`零确认定位` / `只定位零确认` | 只读排查 + 交付包 + **可写** hotfix 草案（§根因/§验证，**禁止** §已修复）；**禁止**改业务代码/运维 | 与 `零确认` 混用时代码仍须 `批准修复` |
| **批准改流程** | `批准改流程文档` / `批准改 orchestrator` | 仅改 `~/.cursor/skills/`、`~/.cursor/commands/` | 不算业务修复授权 |
| **分段** | `批准段 2`（须先有段 2 交付说明） | 该段范围内编码 | Agent 自行进入段 2 |

**编码前自检（必做，不对用户展示）**：改 **业务仓库** 代码/yaml → 须 `批准修复` / `零确认`（代码）/ `批准段 N`。**否 → 不得 Write/StrReplace 业务文件。**

**运维前自检**：删 ES 索引 / reindex → 须 `批准运维` 或 L0 同条 `授权执行恢复`；**须先** reindex 备份步骤。**否 → 只输出 SOP。**

**元讨论 / 流程反馈**（如「一次授权有没有问题」「规则怎么改」）：**永远不算**业务修复授权；改 orchestrator/命令文档须 **`批准改流程文档`**。

### 无效批准（一律驳回 — Agent 不得编码）

| 用户说了什么 | 是否等于 `批准修复` |
|--------------|-------------------|
| `/buc` + 现象 / 根因 / **具体改法**（含 commit、类名、字段名） | ❌ **否** |
| `/bsp` + 「按交付包改」 | ❌ **否** |
| 「把 cascadeState 改回 entity.state」 | ❌ **否**（这是 **L0 改什么**，不是批准） |
| 「授权查询 ES」 | ❌ **否**（只读） |
| 「OK / 继续 / 可以」 | ❌ **否** |
| **单独一条**：`批准修复` / `按推荐修` | ✅ **是** |
| L0 **同条**含 `零确认` / `直接修` / `不用再确认` | ✅ **是**（仅首轮） |

**编码硬门禁 #1 扩展**：须能在对话中 **原文引用** 合法批准句；**禁止**引用 Agent 自己写的「已按您要求执行」作为批准。

### 首轮交付包格式（BUG 默认，未批准前）

```markdown
### 交付包（待批准）   ← 禁止写「已执行」「已完成」

…根因 / 只改 / 影响面 / 怎么验证…

回复 **批准修复** 后同会话编码。**本条禁止**：git diff、Write 业务文件、hotfix §已修复、Phase B。
```

- [ ] **G0-2 机制清单（默认强制）**：**凡 BUG 类任务**已输出 L4 **机制清单表**（见下）；每类标 **已查 / 不适用 / 待查**；禁止只跟一条调用栈

- [ ] **G0-5 高并发基线（默认强制）**：已输出 **高并发评估表**（见下）；热/冷路径已分；含 **频率/cap/批大小/多实例行为/锁或幂等**；热路径 **不加 DB 写** 除非用户批准且论证
- [ ] **G0-6 业务影响复盘（默认强制）**：已输出 **已有业务影响表** + **≥3 条并发/稳定性回归**；说明修复是否叠加/冲突现有定时、Buffer、双写

- [ ] **G0-8 禁自批**：未出现自批、推断批准、模糊肯定当批准、多轮后突然编码；编码前可 **原文引用** 用户批准句
- [ ] **G0-9 闭环四件**：交付包/专项 md 含 **怎么验**、**影响面**、**后续演进**；编码完成摘要可 **复制即验**；验后须填 **验证结果**（未验标待验证）

## Gate 1 — 分层读上下文（L0～L4）

### L0 边界

现象/目标、模块范围、是否回归、明确 **不在范围内**。

### L1 文档层

顺序：`CLAUDE.md` / `README` → `docs/` 相关 → 问题台账 → 决策/ADR → 本主题专项 md。

**输出表**：| 文档 | 结论 | 需修正 |

### L2 结构层

- 有 **codegraph MCP**：**一次** `codegraph_explore` 覆盖现象→写→读→定时/消费
- 列出 **热路径** + **冷路径**（@Scheduled、Flux.interval、Supplement、补偿）

### L3 爆炸半径

对拟改符号：`codegraph_impact` / callers / callees → **爆炸半径表**

### L4 机制清单（BUG 类 **默认强制**，非 BUG 可标不适用）

**范围**：围绕 L0 现象域，扫 **热 + 冷 + 定时 + 补偿 + 展示读法**，不是全仓库逐文件，也不是单条 invoke 链。

**必查类别**（按现象裁剪行，但不可整表省略）：

| 类别 | 扫什么 |
|------|--------|
| 热路径 | 同步/异步入口 → 主写库/写缓存 |
| 定时/调度 | `@Scheduled`、`Flux.interval`、Supplement、补偿任务 |
| 消息/消费 | MQ/Pulsar 订阅、Buffer、批处理、重试 |
| 状态/缓存 | 同表双写、Redis key、TTL、三级缓存 |
| 同步/部署 | FULL/增量、deploy、拓扑/影子设备 |
| 展示/读法 | UI/API 读哪张表/哪个字段（与写路径是否一致） |
| 平台/超时 | 平台级 offline、心跳阈值、级联上下行 |
| **并发/多实例** | 同任务多 Pod 重复跑、分布式锁、去重、Buffer 背压、连接池 |

**输出表（G0-2 交付物）**：| 类别 | 机制/类/方法 | 与现象关系 | 结论 |

「已查无并联」仅当 **全表** 均为「不适用」且说明为何与现象域无关。

### L 层停止条件

能端到端解释现象；能答「改这里还动谁」；文档与代码无未解释矛盾。

**BUG 类任务**（`/bsp` 报 BUG 默认视为 BUG 类）：

1. L2 前增加 **复现**（步骤、期望/实际、是否稳定）——借鉴 [systematic-debugging](https://github.com/spencerpauly/awesome-cursor-skills/blob/main/resources/systematic-debugging/SKILL.md) 的 Reproduce→Isolate→Hypothesize。
2. **L4 机制清单默认强制**（用户已选 **A**）：无需用户提「定时任务」等关键词；Agent 必须主动填表后再出根因/方案。
3. 现象含 **「ES/Kibana 有数据、API/接口空」** → **强制**完成 **§ES 读写 parity 清单**（见 Gate 2 附录）**后**才允许写「根因」。

## Gate 2 — 方案（superpowers + 高并发优先）

### Gate 2 附录 — ES「有数据、接口空」强制清单（未完成 **禁止** 出根因）

**适用**：设备属性/事件/日志、平台 ES 日志等；现象为存储层可见、应用查询为空。

| # | 检查项 | 怎么做 | 通过标准 |
|---|--------|--------|----------|
| T-ES1 | 应用读的 index/alias | 代码 `getIndexForSearch` / `create*Metric` | 写出 **实际** 查询名，非猜测 |
| T-ES2 | 当月 vs 上月 mapping | `_mapping/field/deviceId`（及 property/event 等 term 字段） | 表格对比 **keyword vs text** |
| T-ES3 | **应用同款 term** | `termQuery(字段, 值)` **不带** `.keyword`（对齐 `TermTypeEnum.eq`） | 记录 total |
| T-ES4 | keyword 对照 | 同上条件用 `字段.keyword`（仅野索引有） | 与 T-ES3 对比；T-ES3=0 且 T-ES4>0 → **mapping/term 主因** |
| T-ES5 | alias 绑定 | `_cat/aliases` | 记录绑定索引；**单独**一行，不与 T-ES3 混结论 |
| T-ES6 | Java 是否短路 | `getProperties` / 权限 / 空 mono 等 | 代码路径说明是否在 **发 ES 前** return |
| T-ES7 | API 层验证 | 用户 curl 或等价 ES 查询 | **禁止**仅用 Kibana DevTools 的 `.keyword` 查询宣布「ES 通了」 |

**「ES 层恢复」定义（硬规则）**：

- ✅ 仅当 **T-ES3（应用同款 term）在目标 alias/索引上 total > 0** 时，可说「ES 查询层恢复」
- ❌ **禁止**：Kibana 用 `.keyword` 查到数据 → 推断 API 会好
- ❌ **禁止**：alias 已绑 → 推断 term 必命中（mapping 仍可能是 text）

**交付包必附**（该现象域）：

```markdown
### ES parity 表（T-ES1～T-ES7）
| # | 结果 | 结论 |
| T-ES3 term deviceId | total=? | |
| T-ES4 deviceId.keyword | total=? | |
…
**主因层级**：□ ES mapping/term  □ Java 短路  □ alias 路由  □ 叠加（列明）
```

### 根因版本规则（同一会话 **强制**）

- 新证据推翻旧结论 → 必须写 **`作废 #n：…（为何错）`**，再写 **`当前 #n+1：…`**
- **禁止**不认错直接给相反结论；**禁止**多轮 `/buc` 重启却当作全新案件而不作废旧版
- 多因素并存 → 写 **主因 + 叠加因素 + 时段**（例：「10:07 曾缺 alias；12:00 已绑；term 仍为 0 → mapping 为主因」）
- 专项 md / hotfix §排查记录：**追加**版本行，D5 旧口径标 supersede

**BUG + 直通修复（默认）**：

- **禁止**为走流程而多轮问答；**禁止**未授权编码（见 **授权红线**）
- 首轮：**交付包 + 一句「回复 批准修复 后开始」→ 停**（零确认 L0 除外）
- **阻塞问题最多 1 个**；问完仍 **停**，不得边问边改

**交付包结构（BUG 首轮必用，用户只看这块 + 授权行）**：

```markdown
### 交付包（一页）
- **根因版本**：当前 #1（若有作废须列 **作废 #0**）
- **根因**：（1～3 句；ES 类须引用 T-ES3/4 数字）
- **ES parity**：（若适用，T-ES1～7 摘要表）
- **改什么**：（文件/方法，冷/热路径）
- **只改**：（Agent **必填**，精确到文件/类/方法；编码后 diff 不得超出）
- **禁止碰**：（Agent **必填**；默认含：无关模块、删/清全量、生产默认配置）
- **删写对照**：（若动 delete/remove/invalidate/批量改态 **必填**；否则写「无」）
- **未覆盖场景**：（Agent **必填** ≥1：本地/压测验不到的形态，合入风险）
- **影响面**：（谁读/谁写/调用链/用户可见；见 G0-9 表）
- **高并发**：（cap/频率/多实例，1 段）
- **业务影响**：（与现有定时/任务是否冲突，1 段）
- **怎么验证**：（步骤编号 T1/T7 + SQL/日志 + 通过标准；**修复后你照此执行**）
- **后续演进**：（明确不做 / 可选段 2 / 已知限制 / 技术债）
- **文档**：（**主** `bugfix-readme/hotfix_{BugId}-readme.md`；**归档** `docs/...`）
- **行为 parity**（换路径/对外 API **必填**）：| 检查项 | 改前 | 改后 | 一致？ |
- **配置分环境**（动 TTL/开关 **必填**）：生产默认 / 压测 profile（`application-perf.yml` 或 env）各写什么

回复 **批准修复** → 下一条消息收到后同会话编码+落盘（**本条消息不得编码**）。L0 含 **零确认**（代码）则本条可编码。  
**ES 运维** SOP → 回复 **批准运维** 后执行；**授权查询** → 本条即可 curl，不等批准修复。  
**合 Gerrit 默认用 `/buc`**，勿 `/bsp` 编码后再手动多次 `/code-review`。
```

### G0-5 高并发评估表（方案阶段必附）

| 维度 | 本方案 |
|------|--------|
| 路径 | 热 / 冷（定时/Supplement/消费回调） |

## Gate 3 — 分段设计与批准（非默认）

**默认走直通修复，不分段。** 命中 **Gate 3 自动升分段** 或用户 L0 含「分段」时启用：

- 段 1、段 2… 每段 **独立交付包** + 独立 hotfix §变更（或独立 BugId 子节）
- 每段附 **§G0-1～G0-7**（Agent 自检，**不向用户逐条确认**）
- 等用户 **「批准段 N」**（分段模式）；**禁止** `批准修复` 一次跨段编码
- 段内写：频率、批量、上限、多实例、与现有定时/消费分工边界；**段间不共享未批准改动**

**分段合入顺序**：先 **对外/行为 parity**（段 2 类），后 **性能/缓存**（段 1 类），除非交付包论证相反顺序更安全。

## Gate 4 — 文档落盘（**硬门禁**，与编码同会话）

**只追加**排查/变更记录，不删历史。文档写在 **项目仓库** `docs/`，不是只写在聊天里。

### 4.1 路径优先级

| 优先级 | 路径 |
|--------|------|
| 1 | **`bugfix-readme/hotfix_{BugId}-readme.md`**（**iot-server 合入主文档**，须按 `hotfix_{BugId}-readme-template.md`） |
| 2 | `docs/<模块>/当前有效/` 专项 md（**技术归档 / L4 深挖**，指向 hotfix 主文档） |
| 3 | `docs/<模块>/已知问题.md` 或问题台账 **一行** |
| 4 | 项目 `CLAUDE.md` 文档导航（新主题首次出现时 **加一行入口**） |
| 5 | 决策/ADR（可复用决策时） |

### 4.1.1 BUG 文档分工（iot-server）

| 文档 | 用途 |
|------|------|
| `bugfix-readme/hotfix_{BugId}-readme.md` | **合入/Gerrit/自测/影响面/验证/演进**（模板：`hotfix_{BugId}-readme-template.md`） |
| `docs/.../级联BUG排查-*.md` | L4、mermaid、§变更归档；文首链到 hotfix 主文档 |

### 4.1.2 BUG 专项 md 归档章节（缺章 = G0-9 未过，**表格内容以 hotfix 为准**）

```text
1. 现象与验收
2. 根因与机制（含 L4）
3. 修复方案（含 §高并发、§业务影响）
4. 影响面（G0-9 表）
5. 怎么验证（步骤+SQL/日志）
6. 验证结果（待验/已验，验后填）
7. 后续演进（可选优化、限制、监控）
8. 排查记录（追加，不删历史）
```

### 4.2 三阶段必做（缺任一步 = G0-3 / G0-9 未过）

| 阶段 | Agent 必做 | 用户可见交付 |
|------|-----------|-------------|
| **方案前** | 专项 md：**§4 影响面、§5 怎么验证、§7 演进（草案）** + 根因方案 | 可点击路径 |
| **编码后** | §变更 + §修复后复盘；§6 验证结果 = **待验证**；台账待验证 | **完成摘要含验证清单** |
| **验证后** | §6 填 **验证结果**；台账 **已修复** | 关单 |

状态流转：`待批准` → `待验证` → `已修复/已关闭`；废弃方案标日期与原因。

### 4.3 回复末尾必附（BUG 类，与 Gate 0 一并交付）

```markdown
### 文档落盘（G0-3）
| 路径 | 动作 | 状态 |
| docs/.../xxx.md | 根因+方案 / §变更 / §验证 | 已更新 / 待写 / 待验证 |
| docs/.../已知问题.md | D00x 一行 | … |
```

**禁止**：只改 Java、聊天里口头总结、不落盘仍说「已修复」。

### 4.4 编码后文档对账（补丁轮 / 配置变更 **强制**）

编码完成前 Agent **自检**（completion 摘要须带 D1–D8 结果）：

| # | 检查 | 做法 |
|---|------|------|
| D1 | 旧关键词清零 | 对 hotfix + 链式专项 md **grep** 交付包「改什么」中的**旧名**（配置 key、类名、TTL、已删方法） |
| D2 | 配置三角一致 | `application.yml` ↔ readme「配置/行为变化」↔ 代码 `@ConfigurationProperties` / 常量默认值 |
| D3 | 验证项一致 | T1/T7 中的 TTL、开关名、日志关键字与 yaml / 实现一致 |
| D4 | 专项 md 同轮 | `docs/...` 的 mermaid、§变更 与 hotfix **同轮**更新，不得只改 hotfix 一段 |
| D5 | 排查记录 | **追加**新结论；若改口径则修正旧行或注「已 supersede」，**禁止同文件自相矛盾** |
| D6 | 行为 parity | 动 OpenApi/对外 HTTP 或换 dispatch 路径 → 对照交付包 **parity 表** 自检（成功字段、异常类型、日志、统计注解） |
| D7 | 配置分环境 | 动 TTL/缓存/开关 → 生产默认与压测 profile **分开写**；grep readme 旧 TTL/key = 0 |
| D8 | 启动链 | 新增 `@Component` / 构造器注入 → 脑补 **循环依赖**（尤其 Service↔Cache↔Repository） |

**补丁轮次**（Review 衍生、用户反馈、方案变更）须 **重新执行 D1–D8 全文对账**，不得只改 Java。

文档落盘表状态仅允许：`已对齐` | `待写` | `已废弃`；**禁止**标「已更新」但 grep 仍命中旧描述。
