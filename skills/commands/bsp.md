**触发 `/bsp` 时只做一件事：**

1. **Read** `~/.cursor/skills/bsp-orchestrator/SKILL.md`（**全文**，不可跳过 Gate 0）
2. 再按 **superpowers brainstorming** 执行
3. 用户在本命令后的「我的需求：」即本次 L0 输入

**回复第一行必须是：** `[BSP] 已 Read bsp-orchestrator，Gate 0 起执行。`

**HARD-GATE：** 未通过 **授权红线** → **禁止**改业务代码/配置/迁移（元讨论改 orchestrator 须 **`批准改流程文档`**）。  

**授权三分法（v3）：**

| 口令 | 允许 |
|------|------|
| **`授权查询`** / 给出只读账号 | **立即** ES/DB 只读诊断，**不等** `批准修复` |
| **`批准运维`** / `授权执行恢复` | ES 删索引、reindex、改 alias（**须先备份**） |
| **`批准修复`** / `按推荐修` | 改业务 Java/yaml + 落盘 |
| L0 **`零确认`** | 同条可编码（代码）；**`零确认定位`** = 只读+文档，不改代码/运维 |

默认 **交付包 → 停 → 等 `批准修复`**（运维等 **`批准运维`**，查询见上）。  
**具体改法 / `/buc` ≠ 批准**；首轮标题仅 **「交付包（待批准）」**，禁止同轮 **「已执行」+ diff**。  
**禁自批：** 十几次沟通后突然编码 = **严重违规**；模糊「好的/继续/A」≠ 批准。  
**ES「有数据接口空」**：未做完 **T-ES1～7**（见 `bsp-orchestrator` Gate 2 附录）**禁止**写根因；**禁止**用 Kibana `.keyword` 命中即宣布 API 会好。  
**包办：** 高并发/机制/文档 Agent 内部做；**不等于**可跳过用户授权。  
**闭环：** 每个 BUG 须落盘 **影响面 + 怎么验证 + 验证结果 + 后续演进**（G0-9）；缺任一项不得称完成。

**编码后必做（Gate 4 硬门禁，缺任一项不得称 Phase A 完成）：**

1. **文档全文对账**：hotfix readme + 链式专项 md，grep 交付包「改什么」中的**旧名**（配置 key、类名、TTL 描述）→ 零残留或标「已废弃」
2. **配置三角一致**：`application.yml` ↔ readme「配置」表 ↔ 代码默认值 / `@ConfigurationProperties`；压测 key **分 profile**，勿误改生产默认
3. **业务自检 D6–D8**：OpenApi parity、TTL/开关分环境、Spring 注入无环
4. **回复末尾附「文档落盘表」**（路径 | 动作 | 状态），不得含 **待对齐**

**补丁轮次**（Review 衍生、方案变更、用户反馈）= **新一轮 Gate 4 全文对账（D1–D8）**；禁止只改代码不改 readme 同名章节。

**分段（v2）：** 跨 **>3 文件 + 2+ Maven 模块** 或 **换调用路径** → 交付包标「建议分段」；一次 `批准修复` 不得跨段。

**Review 轮次（v2）：** 合 Gerrit **默认 `/buc`**；**禁止** `/bsp` 编码后再 **多次** `/code-review`。同一 Bug 已编码 → 续用 **`/buc`** 或 **`Review 衍生 #n 批准修复`**。

**Ponytail：** 在 Gate 2～5 内生效；不得突破 Gate 0-5 稳定性约束。

**编码：只认 `bsp-orchestrator` 顶部「编码硬门禁 6 条」**（含：不跑 mvn、不加 test、范围/删写/未覆盖）。KhLinks 编译见 Gate 5 附录。

**扩展：** 要 **编码后自动 Code Review + 有问题回到 BSP**，用 **`/buc`**（见 `~/.cursor/commands/buc.md`）。**合 Gerrit 的 BUG 修复默认 `/buc`**；纯分析/方案用 `/bsp`。
