# `/bsp` 快速使用（同事版）

## 一句话

**`/bsp` = 报 BUG 的标准入口**：Agent 自己扫机制、写方案、落文档；**你只批一次**（或 L0 写零确认）。

---

## 三种用法

### 0. 合 Gerrit（推荐：`/buc`）

```text
/buc

我的需求：
BUG 37037，（粘贴截图或一句话现象）
期望：…
```

→ Phase A 交付包 → 你回 **`批准修复`** → Agent 编码 + **自动 Code Review**  
→ Review 有 P0/P1 → Review 衍生 #n 交付包 → 再批一次（最多 3 轮代码修复）

---

### 1. 标准 BSP（保留一次把关，不含自动 Review）

```text
/bsp

我的需求：
BUG 37037，（粘贴截图或一句话现象）
期望：…
边界：…（可选）
```

→ Agent 给 **交付包（一页）** → 你回：

```text
批准修复
```

→ Agent **同会话**改代码 + 写 `docs/`，最后给 **「修复完成（待验收）」** 摘要。

---

### 2. 零确认（完全信任时）

```text
/bsp

我的需求：
BUG 37037 …
直接修，不用再确认。
```

→ 首条 L0 **必须**含 `直接修` / `不用再确认` / `零确认`。

---

### 3. 只有截图

```text
/bsp

我的需求：
BUG 单只有截图，请从图里提取 ID 和现象，按 Gate 0 出交付包。
验收：与源平台一致，6 分钟内。
```

---

## 交付包长什么样

Agent 首轮应给你 **一页**，包含：

- 根因 · 改什么 · **影响面** · 高并发 · 业务影响  
- **怎么验证**（T7 + SQL/日志，可复制执行）  
- **后续演进**（可选优化 / 已知限制）  
- 文档路径（`docs/.../xxx.md`）

**不需要**你回忆定时任务、Supplement、Redis 双写等——Agent 内部做。

---

## 修完后你要做什么

1. 打开完成摘要里的 **怎么验证**，在测试环境执行（如 T7 + SQL）  
2. 通过 → 回复 **`T7 通过`** 或 **`验收通过`**  
3. Agent 更新专项 md **§验证结果** + 问题台账 **已修复**

---

## 授权红线（防 Agent 乱改）

| ✅ 算批准 | ❌ 不算批准 |
|-----------|-------------|
| `批准修复` | 单独「好的」「继续」「A」 |
| `按推荐修` | 补充现象、批评流程 |
| L0 同条 `直接修` | Agent 自己说「默认批准」 |

未收到批准 → Agent **不得**改业务 Java/配置。

---

## 验收 Agent 是否按规则干活

合格回复应包含：

1. 第一行：`[BSP] 已 Read bsp-orchestrator，Gate 0 起执行。`  
2. **交付包** 含：影响面、怎么验证、后续演进  
3. 编码完成后：**怎么验证（复制执行）** + 文档路径  
4. **未批准前**没有业务代码 diff

不合格时可说：

```text
G0-8 违规，未收到批准修复，先交交付包。
```

或：

```text
G0-9 没过，补影响面/怎么验证/验证结果/演进。
```

## 常见问题

**Q：和 `/bs` 区别？**  
A：`/bs` 纯头脑风暴；`/bsp` = BUG 编排 + 文档 + 高并发；`/buc` = `/bsp` + 自动 Review 闭环（合 Gerrit 默认）。

**Q：/bsp 和 /buc 选哪个？**  
A：只分析或不想自动 Review → `/bsp`；要编码 + Review 一次走完 → `/buc`。

**Q：必须装 Superpowers 吗？**  
A：不必须；`/bsp` 命令会 Read `bsp-orchestrator`，核心 Gate 仍生效。

**Q：文档写在哪？**  
A：业务仓库 `docs/<模块>/当前有效/` 专项 md，不是只写在聊天里。

**Q：安装失败？**  
A：看 [`INSTALL.md`](INSTALL.md)，确认 `~/.cursor/skills/bsp-orchestrator/SKILL.md` 存在后重启 Cursor。
