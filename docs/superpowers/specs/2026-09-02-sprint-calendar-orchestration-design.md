# 设计稿：冲刺日历全链路整改

> 日期：2026-09-02  
> 目标：以 `05-Interview-Prep/冲刺日历-2026-09-02.md` 为 2026-09-02～12-15 唓一执行入口，补齐真实项目深追、每日验收和投递反馈闭环。  
> 用户批准：2026-09-02 已批准全链路编排方案，并明确要求“必问题只要项目真实用过，就必须说明项目怎么用并带钩子；没用过则明确降级”。

## 1. 问题定义

当前仓库不是缺少题目，而是存在四类结构问题：

1. `README`、学习路径、W1 手册、冲刺日历同时承担“今天做什么”，入口冲突。
2. 9 月部分日期过载，10 月只有周主题，11～12 月只有投递 KPI，无法按天执行。
3. IoT 主线已有深度，但 ERP、MySQL/Redis/JVM 通用题与真实项目绑定不足；部分官方题只在末尾硬贴一句项目钩子。
4. EventBus/Pulsar、operatorCache、8G OOM/32G GIIC 存在口径冲突；模拟复盘、投递跟踪、面试复盘缺少实体文件。

## 2. 设计原则

### 2.1 单一执行入口

每日只走：

```text
PROGRESS_LOG 当前快照
  → 冲刺日历当天
  → P0 口述/录音
  → P1 当日主任务
  → P2 可选
  → 【今日收工】
  → 复盘缺口回灌后续日历
```

`PLAN.md` 只说明总目标；`学习路径与面试串讲.md` 只做知识和故事索引；旧 W1 手册保留为历史证据期材料，不再参与冲刺期排课。

### 2.2 必问题的真实项目门禁

七个必问维度：业务场景、并发、MySQL、MQ、性能、压测、优化。

项目真实使用过的题，必须具备：

1. 真实场景和本人角色；
2. 项目中的具体用法；
3. 数字及 `[文档]/[反推]/[假设]/[实测]` 证据态；
4. 机制；
5. Why、代价和替代方案；
6. 连续 3～5 个追问；
7. 换场景迁移；
8. 能自然带回项目的钩子或反抛；
9. 负责、协助、禁改、非 owner 边界。

项目未使用过的题必须标为“了解级/官方变体”，只回答通用骨架，不声称生产实践，不作为主动引导方向。

### 2.3 每日投入

- 9 月：2h/天。
- 10 月：工作日 60～90min；休假轻量日 30min。
- 11 月起：40min 复习 + 投递/面试动作。
- 学员可在每日开工时按实际时间降级，但不得跳过 P0。

### 2.4 事实边界

- 主定位：5 年+ Java 后端（IoT 平台），11 年 Java 信用 + 1 年+ IoT 现网。
- GIIC 只主讲 15W CoAP-TCP、5000 msg/s、96h；40W/20W 为背景或协助，不说 owner。
- 设备上报第一跳为 iot-server EventBus；Pulsar 仅用于级联/跨服务等已证链路。
- OOM 案例为 `-Xmx8G`、约 5050 台、Dominator 约 5.7G/78%；GIIC 32G 是另一条容量规划线。
- `D:\gerrit\iot-server` 只读；证据只写本仓。
- ERP 只使用已存在且可证的 300+ 商户、日峰值 3000 万、分布式锁/幂等/唯一约束/状态机口径；未知表结构、事故和优化结果不得编造。

## 3. 内容架构

### 3.1 唯一事实索引

新建 `05-Interview-Prep/数字与边界-唯一索引.md`，集中维护链路、数字四态和角色边界。其他口述材料可复制口径，但必须注明索引章节。

### 3.2 连环深追脚本

新建 `05-Interview-Prep/面试连环深追脚本.md`。每个必问维度固定为：

```text
入口问 → 项目开口 → 机制 → 数字/证据 → Why/代价
→ 追问 1～5 → 换场景 → 钩回项目/反抛 → 边界
```

### 3.3 官方题分级

- 强绑定：秒杀/幂等、连接路由、一致性哈希、缓存、MQ 积压、容量、故障定位，进入主练。
- 弱绑定：推荐、广告、纯算法大数据题，降为了解级。
- 不允许用“同构”一句话把没做过的官方方案伪装成项目经验。

## 4. 日历架构

### 4.1 9 月

逐日包含 P0/P1/P2、文件章节/题号、时间盒、验收和降级。完成三故事、七维主线、简历、四次模拟、JD 映射和投递物料。

### 4.2 10 月

按日期分配 MySQL/Redis/网络/Netty/JVM/综合深追题号。每题强制说项目锚点；无锚点则说“了解级”。完成模拟 #5。

### 4.3 11～12 月

按周给固定日节奏：岗位筛选、投递、对口复习、模拟/真面试、24h 复盘、gap 回灌、周统计。投递量服从质量门禁。

## 5. 闭环文件

- `口述稿/_复盘模板.md`：模拟与真面试统一字段。
- `口述稿/mock-01～05-复盘.md`：预建入口。
- `投递跟踪表.md`：岗位、JD、状态、下一动作。
- `面试复盘日志.md`：原题、回答、断点、证据、回灌题号、复测日期。

录音保存在手机即可，但 Markdown 必须记录日期、时长、流畅度、卡壳点，作为可读验收证据。

## 6. 验收标准

- [ ] 冲刺日历覆盖 09-02～12-15，9 月逐日、10 月逐日题号、11～12 月固定周节奏无空档。
- [ ] 每天最多 P0/P1/P2 三项，并包含路径、章节/题号、时间和验收。
- [ ] 七个必问维度均通过九项门禁；没做过的明确降级。
- [ ] 三处技术口径冲突清零。
- [ ] 三故事、七维、JD 雷达、K8s 防守、简历、模拟、投递、复盘均进入日历。
- [ ] README、PLAN、PROGRESS_LOG、规则和协作约定只指向一个冲刺入口。
- [ ] 所有新增/引用文件存在，模拟复盘路径统一。
- [ ] 两路独立审查无未解决 P0/P1；主 Agent 完成 diff、`rg`、`Test-Path` 和 spec 逐项验收。
