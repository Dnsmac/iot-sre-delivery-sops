# 压测评估基于实际数据（正确方法 · 2026-07-23）

> **核心原则**：基于实际数据计算，不是理论公式  
> **错误做法**：峰值乘以3、冗余乘以1.5（完全错误）  
> **正确做法**：基于实际连接数、实际QPS、实际数据大小计算

## 一、正确理解

### 1.1 峰值是固定的
- 压测中的峰值是确定的，不是随意乘以3
- 例如：15万连接就是15万连接，不是15万×3=45万

### 1.2 拥堵才会造成高峰
- 冗余是为了应对拥堵，不是为了应对峰值
- 例如：如果担心Redis拥堵，可以增加Redis内存
- 例如：如果担心MySQL拥堵，可以增加MySQL连接池

### 1.3 按实际出发
- 基于实际连接数、实际QPS、实际数据大小计算
- 不要用理论公式，要用实际数据

## 二、GIIC 15万案例（基于实际数据）

### 2.1 实际业务参数
- 连接数：150,000（15万）
- 每秒请求数：5,000（5千QPS）
- 每次请求数据大小：1KB
- 每连接内存：10KB
- 应用连接池大小：100
- 应用实例数：4

### 2.2 带宽计算（基于实际数据）
**计算方法**：
```
每秒总数据量 = 每秒请求数 × 每次请求数据大小
例如：5,000 × 1KB = 5,000KB/秒

带宽(Mbps) = 每秒总数据量(KB) × 8 / 1024
例如：5,000 × 8 / 1024 = 39Mbps
```

**实际结果**：需要**39Mbps带宽**

**为什么不需要乘以系数**：
- 峰值是固定的：15万连接就是15万连接
- 拥堵才会造成高峰：如果担心拥堵，可以增加带宽
- 按实际出发：基于实际数据计算，不是理论公式

### 2.3 CPU计算（基于实际数据）
**计算方法**：
```
每秒总CPU时间 = 每秒请求数 × 每请求CPU时间(ms)
例如：5,000 × 10ms = 50,000ms/秒

CPU核数 = 每秒总CPU时间(ms) / 1000 / CPU利用率
例如：50,000 / 1000 / 0.7 = 71.4核
```

**实际结果**：需要**72核CPU**

**为什么不需要乘以系数**：
- 峰值是固定的：5,000 QPS就是5,000 QPS
- 拥堵才会造成高峰：如果担心拥堵，可以增加CPU
- 按实际出发：基于实际数据计算，不是理论公式

### 2.4 内存计算（基于实际数据）
**计算方法**：
```
连接内存 = 连接数 × 每连接内存(KB) / 1024 / 1024
例如：150,000 × 10 / 1024 / 1024 = 1.43GB

Redis内存 = 连接数 × 每连接Redis内存(KB) / 1024 / 1024
例如：150,000 × 1 / 1024 / 1024 = 0.14GB

MySQL内存 = 缓冲池大小 + 连接内存 + 系统预留
例如：8GB + 400 × 10MB / 1024 + 2GB = 11.9GB

ES内存 = 索引内存 + 查询内存 + 系统预留
例如：2GB + 1GB + 2GB = 5GB

系统预留 = 2GB

总内存 = 连接内存 + Redis内存 + MySQL内存 + ES内存 + 系统预留
例如：1.43GB + 0.14GB + 11.9GB + 5GB + 2GB = 20.47GB
```

**实际结果**：需要**20.47GB内存**

**为什么不需要乘以系数**：
- 峰值是固定的：15万连接就是15万连接
- 拥堵才会造成高峰：如果担心拥堵，可以增加内存
- 按实际出发：基于实际数据计算，不是理论公式

```

单进程最大连接数 = min(文件描述符限制, 端口范围, 系统限制)
```
