## 6. 容量测算（450 B/msg 文档值 · 待补实测）

> **证据调查（2026-09-02）**：450B 目前只出现在本文，仓内 `evidence/` 仅有 GIIC JMeter Dashboard 截图，未找到原始抓包、脚本 `len(...)` 输出、网卡增量或 ES 增量证据。
> **使用边界**：450B 只能标 `[文档/待补实测]`，不能标 `[实测]`，也不能作为交接与验收的唯一真值。`1KB×3`、152Mbps、620GB/天保留为历史保守 `[假设]`；主答应说明抓包和 ES 增量实测尚未完成。

### 6.1 输入表

| 符号 | 值 | 来源 |
|------|-----|------|
| N | 150,000 | 在线 TCP |
| Q_msg | 5,000 /s | 集群属性 Data 验收 |
| T_period | N / Q_msg = **30 s/台** | 反推 |
| B_msg | **≈450 B/条** | `[文档/待补实测]`（一条 Data msg 含多属性时的 body 总长，原始输出缺失） |
| N_node | 4 | 业务节点 |
| C_inst | N / N_node = **37,500** /实例 | 反推 |
| props/msg | ~3（仍按属性拆 ES 时） | 物模型/脚本；**450 B 是整包非单属性** |

### 6.2 带宽

**属性 Data 上行（明文 payload）**

```text
字节/秒 = Q_msg × B_msg
        = 5000 × 450
        = 2,250,000 B/s

MB/s   = 2,250,000 / 1024² ≈ 2.15 MB/s
Mbps   = 2,250,000 × 8 / 10^6 = 18 Mbps
```

**CoAP-TCP 线路（加密后，粗估 ×1.2～1.5）**：约 **22～27 Mbps**（口播「二十多兆」）。

**下行 ACK**（仍按规划假设 200 B/条）：`5000 × 200 × 8 / 10^6 ≈ 8 Mbps`

**心跳**（假设 150k/60s，200 B/次）：`2500 × 200 × 8 / 10^6 ≈ 4 Mbps`

**合计（属性+ACK+心跳）**：约 **30～35 Mbps**（万兆内 **<0.5%**）。

| 项 | 历史保守 `[假设]`（1KB×3） | 450B 文档值 `[文档/待补实测]` |
|----|-----------------|----------------------|
| 属性上行 | ~120 Mbps | **~18 Mbps** |
| 合计 | ~152 Mbps | **~30～35 Mbps** |

### 6.3 存储（ES · 仍按属性点写）

**docs/s**（若一条 msg 拆 3 个属性点时序文档）：

```text
docs/s = Q_msg × props/msg = 5000 × 3 = 15,000 docs/s
```

**单 doc 粗估**（按待核对的 450B 文档值均分 3 属性，仅作假设演算；不是 ES 增量实测）：

```text
avg_doc ≈ 450 / 3 ≈ 150 B（+ deviceId/propertyId/timestamp 索引 overhead 后按 150～250 B 估）

日增(raw) = docs/s × 86400 × avg_doc / 1024³
          = 15000 × 86400 × 150 / 1024³
          ≈ 181 GB/天（单副本 raw）

规划余量 ×1.3 → ≈ 235 GB/天/副本
replicas=1     → ≈ 362 GB/天
```

**注意**：ES **不存** CoAP 加密整包；**155GB iot buffer**（10W case）是 **写 ES IO 堵**，与上式「写得进」的理论值无关。

### 6.4 内存（与 msg 450 B 的关系）

| 类别 | 量级 | 算式 / 说明 | 是否随 450 B 变 |
|------|------|-------------|-----------------|
| **连接常驻** | **~440 MB/实例** | scalability-plan 逐项：Netty/CoAP/PSK/Session/Operator × 37,500 | **否**（看连接数） |
| **AES 密钥 Caffeine** | **~5.6 GB/实例** | 150KB × 150000 / 4 | **否** |
| **物模型 Caffeine** | 0.5～1.5 GB | 5～20KB × 37,500 | **否** |
| **Young 短生命周期** | ~500 MB 峰值 | 1250 msg/s/实例 × **~20 KB/条处理对象**（设计）；**≠ 线路 450 B** | 处理链对象更大 |
| **稳态堆** | ~8～10 GB | 设计 §1.3 | — |
| **申请 -Xmx** | **32 GB** | ≈3× 稳态（Login/GC 尖刺） | — |

**128G 混部 MySQL**：

```text
mysql_budget ≈ 128 - 32(JVM) - 8(OS) - 2(其他) ≈ 86G → prod-128g（MySQL RSS 18～22G）OK
```

### 6.5 公式速查（下一场压测替换 B_msg 即可）

```text
周期(秒/台)     = N / Q_msg
带宽 Mbps       ≈ Q_msg × B_msg × 8 / 10^6          （B_msg 待抓包/脚本实测）
ES docs/s       ≈ Q_msg × props_per_msg
ES GB/天        ≈ docs/s × 86400 × avg_doc / 1024³ × (1+replicas) × 1.3
连接 MB/实例    ≈ Σ(单连接对象 KB) × C_inst / 1024   （与 B_msg 无关）
```

**待补实测**：压测 Data 脚本记录 `len(body.getBytes(UTF_8))` 的原始输出；网卡增量按 `B/msg ≈ 网卡字节增量 ÷ 消息数` 交叉核对；ES 用固定窗口的 `store.size/docs.count` 增量核对，三者落盘后才允许升级为 `[实测]`。

## §0.2 容量测算（450 B/条 Data msg 文档值 · 待补实测）

> **数字来源状态**：本文记录 **单条属性 Data 消息 body ≈ 450 B**，但仓内没有对应原始抓包/脚本输出，故标 `[文档/待补实测]`。
> **旧规划** `giic-150k-scalability-plan.md` 的 1KB×3、152Mbps、620GB/天均为历史保守 `[假设]`；两套数字都不能冒充唯一实测值。

### 输入

| 项 | 值 |
|----|-----|
| 在线 | 150,000 TCP |
| 属性 Data | **5,000 msg/s**（集群） |
| 上报周期 | 150000/5000 = **30 s/台** |
| **B_msg** | **≈450 B/条**（`[文档/待补实测]`） |
| 节点 | 4；**37,500 连接/实例** |

### 带宽

```text
属性上行：5000 × 450 × 8 / 10^6 = 18 Mbps（明文 payload）
CoAP 加密后粗估：×1.2～1.5 → 约 22～27 Mbps
ACK：5000 × 200B × 8 / 10^6 ≈ 8 Mbps
心跳：2500 × 200B × 8 / 10^6 ≈ 4 Mbps
合计：约 30～35 Mbps（万兆 <0.5%）
```

### ES 存储（属性拆点写）

```text
docs/s = 5000 × 3 ≈ 15,000（仍按每 msg 约 3 属性点）
avg_doc ≈ 150 B 量级（450/3 粗分；数值型可能更小）
日增 ≈ 15000 × 86400 × 150 / 1024³ ≈ 181 GB/天/副本（raw）
规划磁盘：×1.3 余量；replicas 按环境
```

### 内存（与 450 B 无关的部分）

| 项 | /实例 | 说明 |
|----|-------|------|
| 连接对象 | **~440 MB** | Netty/CoAP/PSK/Session/Operator 逐项（scalability-plan） |
| 密钥缓存 | **~5.6 GB** | 150KB×150k/4 |
| 稳态堆 | **~8～10 GB** | 含 Young 峰（处理对象 ~20KB/条，≠ 线路 450B） |
| **-Xmx** | **32 GB** | ≈3× 稳态 |

### 公式（下一场替换 B_msg）

```text
Mbps ≈ Q_msg × B_msg × 8 / 10^6
ES GB/天 ≈ Q_msg × props/msg × 86400 × avg_doc / 1024³ × (1+replicas) × 1.3
连接 MB/实例 ≈ Σ(单连接 KB) × 37500 / 1024   （只看连接数，不看 B_msg）
```
