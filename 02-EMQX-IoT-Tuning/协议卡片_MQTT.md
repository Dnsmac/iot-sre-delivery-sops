# 协议卡片 · MQTT（5 张 · 各 30s 脱稿）

> 定位：MQTT 是 IoT 岗「换协议/挖底层」必问，本卡 5 题覆盖机制层，配合 [选型深挖卡①内嵌 MqttServer](../05-Interview-Prep/选型深挖-为什么这么设计.md) 一起用。
> 用法：遮住口径，各 30s 说一遍，说漏再看。

---

## 卡 M1 · QoS 0 / 1 / 2

- **QoS 0**：发完不管，至多一次，可能丢（适合心跳/状态，丢得起）。
- **QoS 1**：PUBACK 确认，至少一次，**可能重复** → 消费端幂等兜底。
- **QoS 2**：PUBLISH→PUBREC→PUBREL→PUBCOMP 四次握手，恰好一次，开销翻倍。
- **口径**：上报用 QoS1 + 业务幂等，不为「不重复」付 QoS2 的代价。

## 卡 M2 · keepalive / 半开连接

- 客户端定时 PINGREQ，服务端 **1.5 × keepalive** 超时判死踢下线。
- 目的：防半开连接（网线拔了对端不知道）堆积占内存/句柄。
- **口径**：防半开连接堆积，配合水位拒连做自我保护。

## 卡 M3 · 会话保持 cleanSession

- `cleanSession=false`：Broker 保留订阅关系 + 离线 QoS1 消息，客户端重连补发。
- `true`：断线即清空。
- **口径**：设备频繁休眠唤醒靠「会话保留 + 消息过期控制」，不靠每连重订阅。

## 卡 M4 · 下行路由

- 设备上线 `SUBSCRIBE device/{id}/cmd`，平台对主题 `PUBLISH` 下发。
- 离线设备消息入缓存/队列，上线补发；在线直接走会话路由。
- **口径**：iot-web → EventBus → 内嵌 MqttServer 会话路由（本平台下行链）。

## 卡 M5 · retain

- Broker 存主题**最后一条**，新订阅者立即收到 —— 适合「最新状态」。
- **坑**：指令类主题禁用（新上线会收到旧指令）。
- **口径**：retain 只给状态快照，指令走普通 PUBLISH + 幂等 ID。
