## 目标

用 Pulsar 实现 **订单创建事件** 链路：分区 Topic + Key + Key_Shared 保证同订单有序，DLQ 处理失败，并能在 Admin 上验证。

## 业务假设

- 事件：`OrderCreated`（orderId, userId, amount, createdAt）
- 生产者：`order-api`
- 消费者：`inventory-service`（扣库存）、`notification-service`（发通知）— **两个 Subscription**

---

## 步骤 1：创建 Topic（8 分区）

```powershell
docker exec pulsar-standalone bin/pulsar-admin topics create-partitioned-topic `
  persistent://dev/test/order-created -p 8
```

验收：`topics partitioned-stats` 显示 8 个 partition。

---

## 步骤 2：Producer

要求：

- `key = orderId`
- Batching + LZ4
- 异步 send + 失败日志

可参考 `ProducerDemo`，Topic 改为 `order-created`。

**自测：** 同一 orderId 连发 20 条带序号消息。

---

## 步骤 3：Consumer（inventory-service）

```java
.subscriptionName("inventory-service")
.subscriptionType(SubscriptionType.Key_Shared)
.keySharedPolicy(KeySharedPolicy.stickyHashRange())
.deadLetterPolicy(DeadLetterPolicy.builder()
    .maxRedeliverCount(3)
    .deadLetterTopic("persistent://dev/test/order-created-dlq")
    .build())
```

**自测：** 同 orderId 序号单调；故意抛异常 4 次后进 DLQ。

---

## 步骤 4：第二消费者（notification-service）

- 相同 Topic，**不同** `subscriptionName("notification-service")`
- 验证两服务各收到全量事件（Pulsar 多订阅优势）

---

## 步骤 5：Admin 验证

```powershell
docker exec pulsar-standalone bin/pulsar-admin topics stats persistent://dev/test/order-created
docker exec pulsar-standalone bin/pulsar-admin topics peek-messages `
  persistent://dev/test/order-created-dlq -s inventory-service -n 5
```

---

## 验收标准

- [ ] 同 `orderId` 消息在单 Consumer 内有序
- [ ] 两个 subscription 各自独立消费全量
- [ ] 失败消息进入 DLQ 且可 peek
- [ ] stats 中 `msgRateIn` ≈ `msgRateOut`（稳态无积压）
- [ ] 能画序列图：下单 → Pulsar → 库存/通知
