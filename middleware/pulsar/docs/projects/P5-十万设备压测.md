# 项目 P5：10W 设备压测（综合毕业项目）

> 深度：全文加深 ✓ | 预计 1~2 周 | 优先级 P3 | 运维详 [C11](../part-c-ops/C11-十万设备压测.md)

在 **Cluster** 上完成设备遥测场景的容量验证，产出签字报告（QPS、P99、backlog、磁盘），并验证 **Key_Shared + 分区 + deviceId Key** 设计。

## 一、Topic 设计（定稿）

```
persistent://company-stress/iot/device-telemetry
  分区: 64（起步，按压测调整）
  Producer: key=deviceId, batching+LZ4
  Consumer: Key_Shared, subscriptionName=device-processor
```

**禁止：** 10W Topic、10W 分区。

---

## 二、压测阶梯

| 阶段 | 模拟设备数 | 时长 | 通过标准 |
|------|------------|------|----------|
| 1 | 1,000 | 30 min | 无错误、backlog 稳定 |
| 2 | 10,000 | 2 h | ADD_ENTRY P99 < 20ms |
| 3 | 50,000 | 4 h | backlog 不持续涨 |
| 4 | 100,000 | 4 h+ | 签字指标全绿 |

本地 Standalone：**仅跑阶段 1 冒烟**（`pulsar-loadtest`）。

---

## 三、执行

```powershell
# 本地冒烟（改 loadtest.properties）
cd examples\java\pulsar-loadtest
mvn -q compile exec:java -Dexec.mainClass="com.demo.pulsar.loadtest.LoadTestRunner"
```

Cluster：多机分布式 Runner 或 `pulsar-perf`（运维协助）。

## 四、必采指标

| 指标 | 来源 |
|------|------|
| msgRateIn/Out | topics stats / Grafana |
| backlog | subscription stats |
| ADD_ENTRY P99 | Bookie metrics |
| Broker 连接数 | Broker metrics |
| Bookie 磁盘 | 节点 df |
| 乱序抽样 | 同 deviceId 序号检测 |

## 五、报告模板（交付物）

1. 测试环境拓扑图
