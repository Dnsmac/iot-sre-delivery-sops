# C1 集群部署

> 优先级: **P3 运维** | 深度：批次 4 ✓

## 本章解决什么问题

选择部署模式、理解各组件角色、最小生产拓扑与 Helm/Docker 落地要点。

---

## 一、部署模式对比

| 模式 | 组件 | 场景 |
|------|------|------|
| **Standalone** | 单容器 All-in-One | 开发、功能验证 |
| **Cluster** | ZK/Oxia + Broker + Bookie | 压测、中小生产 |
| **Docker Compose** | 多容器模拟 Cluster | 团队联调 |
| **Helm on K8s** | 生产主流 | 弹性、滚动升级 |

本仓库本地：`docker/docker-compose-standalone.yml` + `scripts/standalone-up.ps1`。

---

## 二、角色分离（必记）

| 角色 | 职责 |
|------|------|
| **Broker** | 接入、路由、ManagedLedger 缓存，**不持久化消息体** |
| **Bookie** | BookKeeper 存储 Ledger |
| **Metadata** | ZooKeeper 或 Oxia（3.x）存元数据 |
| **Proxy** | 聚合客户端连接（大规模 MQTT/设备） |
| **Bookie Autorecovery** | 副本修复（生产建议开） |

最小生产参考：**3 ZK + 3 Broker + 3 Bookie**（奇数副本），跨机架部署 E-Q-W 副本。

---

## 三、Cluster 部署步骤（概要）

1. 准备主机/节点、时间同步（NTP）、主机名解析。
2. 部署 ZK/Oxia 集群并健康检查。
3. 部署 Bookie，格式化 journal/ledger 目录（**SSD journal**）。
4. 部署 Broker，配置 `clusterName`、`zookeeperServers`、`managedLedgerDefaultEnsembleSize` 等。
5. `pulsar-admin clusters`、`tenants`、`namespaces` 初始化。
6. 配置 TLS、JWT、Prometheus。
7. 冒烟：`pulsar-client produce/consume`。

---

## 四、Helm/K8s 要点

- 使用官方或 StreamNative Helm Chart，分离 Broker/Bookie StatefulSet。
- Bookie 必须 **PVC + StorageClass（SSD）**。
- `advertisedAddress` 与 Service 对齐（见 [P10](../part-d-problems/P10-K8s问题.md)）。
- 滚动升级顺序：Broker → Bookie（参照发行说明）。
