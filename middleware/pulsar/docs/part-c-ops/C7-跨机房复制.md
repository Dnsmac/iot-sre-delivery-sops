# C7 Geo-Replication

> 优先级: **P3 运维** | 深度：批次 4 ✓

## 本章解决什么问题

跨机房复制 Topic 的配置方式、最终一致性含义、延迟与冲突处理。

---

## 一、核心概念

- **异步复制**，各集群可独立写入（配置决定）。
- **最终一致**：复制 lag 内，远端读者看到旧数据。
- 组件：Cluster、Namespace `replication_clusters`、Replicator。

```
Cluster-us-east  ──复制──►  Cluster-eu-west
     │                              │
  Producer/Consumer            Consumer（只读或双活）
```

面试答法见 [A10](../part-a-interview/A10-高级特性.md)。

---

## 二、配置概要

```bash
pulsar-admin clusters create eu-west --url http://eu-broker:8080 ...
pulsar-admin namespaces set-clusters persistent://company/global \
  --clusters us-east,eu-west
```

Topic 在 `global` namespace 下自动成为 **Replicated Topic**（版本细节以官方文档为准）。

---

## 三、运维关注

| 指标 | 说明 |
|------|------|
| Replication lag | 复制延迟，告警阈值按 RPO |
| 带宽 | 跨专线/公网成本 |
| 冲突 | 双活写同一逻辑实体需业务版本号 |

---

## 四、适用场景

| 适合 | 不适合 |
|------|--------|
| 灾备、就近读 | 强一致跨机房事务 |
| 全局审计汇聚 | 低延迟强一致交易核心 |

---

## 五、易错点

1. 以为 Geo = 同步双活无冲突。
2. 未监控 lag，故障时 RPO 超预期。
3. Retention 两端不一致导致 seek 行为不同。
