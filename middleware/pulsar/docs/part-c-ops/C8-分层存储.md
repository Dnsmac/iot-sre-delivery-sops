# C8 分层存储

> 优先级: **P3 运维** | 深度：批次 4 ✓

## 本章解决什么问题

把冷数据 Offload 到 S3/GCS 降低 Bookie 磁盘压力，以及冷读 SLA 如何验证。

---

## 一、架构

```
热数据 → BookKeeper 本地 Ledger（低延迟读写）
冷数据 → Offload 到对象存储（S3 / GCS / 兼容）
         元数据仍在 BK，读时拉回或直读（视实现）
```

---

## 二、何时启用

- Retention 长（30~90 天）且写入量大。
- [P11](../part-d-problems/P11-Bookie磁盘满.md) 磁盘反复告警。
- 可接受冷数据 **P99 读延迟升高**。

---

## 三、配置要点（概念）

- Namespace 级 `tieredStoragePolicy`。
- 配置 offload driver（S3 bucket、credentials）。
- 触发：Ledger 达到年龄/大小自动 offload，或 `trigger-offload`。

```bash
pulsar-admin topics offload persistent://company/logs/app-log --threshold 100M
```

---

## 四、验证

1. offload 前后对比 Bookie 磁盘占用。
2. 对**只读历史** Consumer 压测冷读延迟。
3. 恢复测试：对象存储不可用时行为。

---

## 五、易错点

1. 未压测冷读就承诺 SLA。
2. 对象存储权限过期导致读失败。
3. 以为 offload 后无需 Retention 策略。
