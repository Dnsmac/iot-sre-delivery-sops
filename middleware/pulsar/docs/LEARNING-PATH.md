## 二、一条知识主线（全仓库串起来）

面试和自学都按**同一条故事**讲，不要按 A1→A12 字母顺序背。

```
【定位】Pulsar 是什么、和 Kafka 差在哪          → A1 + 附录 B
【骨架】谁存数据、谁接入、元数据在哪            → A2、A11（BK）
【资源】Tenant/NS/Topic、分区、持久化           → A3、A4
【消费】四种订阅、多 Subscription、Cursor       → A5
【语义】ACK、至少一次、重复从哪来               → A6
【生命周期】TTL/Retention/Compaction/积压策略   → A7
【失败】NACK、Retry、DLQ                       → A8
【契约】Schema、BACKWARD                        → A9
【加分】事务/Geo/Tiered/KoP                   → A10（面试加分）
【规模】瓶颈、10W 设备 Topic 设计              → A12
        ↓
【动手】Client → Producer → Consumer            → B1~B3
【协作】多服务、命名、配置                      → B4、B8
【排障】丢/重/乱/慢                             → B9 + Part D
【调优】金字塔 batch/分区/集群                 → B10、B11
【环境】Standalone ≠ 生产                       → B12
【你们】Shared→Key_Shared、关 Auto-Create       → B13、P4、K/K′
```

**记住这一句（自己的话）：**  
「Pulsar 把消息存在 BookKeeper，Broker 负责接入；一个 Topic 可以有多个 Subscription 各自消费；我们业务要用 Key_Shared + 分区保证设备有序，不能长期 Shared 非分区。」

## 三、面试怎么讲（开场 → 深入 → 结合项目）

### 3.1 30 秒开场（背熟再改写）

> 我系统学过 Pulsar，它是存算分离的消息平台，消息持久化在 BookKeeper，Broker 做接入和路由。和 Kafka 比，它原生支持多租户、同一 Topic 上多个独立订阅，还有 Key_Shared 这种按 Key 有序又并行的消费模式。我们项目里用 Java Client，正在把 Shared 非分区改成 Key_Shared 加分区，配合预建 Topic 和 DLQ。

### 3.2 3 分钟结构（面试官最常要）

| 分钟 | 讲什么 | 对应章节 |
|------|--------|----------|
| 0~1 | 是什么 + 存算分离一张图 | A1、A2 |
| 1~2 | Topic/订阅/ACK/至少一次 | A4、A5、A6 |
| 2~3 | 和 Kafka 一点对比 + **你们现状与改造** | 附录 B、B13、P4 |

### 3.3 追问往哪引（不要散）

| 面试官问 | 你先答一句 | 深入文档 |
|----------|------------|----------|
| 架构 | Broker 无状态，数据在 BK | A2、A11 |
| 为什么重复消费 | 至少一次，要幂等 | A6、P2 |
| 怎么保证顺序 | Key_Shared + Key + 分区 | A5、P3 |
| 消息会丢吗 | 持久化 + 发送确认 + Retention | A7、P1 |
| 和 Kafka 选型 | 多订阅、多租户、设备有序 | A1、附录 B |
| 你们生产问题 | Shared 乱序、Auto-Create 风险 | B13、K′、P4 |

### 3.4 变成「自己的」（必做练习）

每天学完在日志里写 **1 句项目结合**（模板）：

```text
今天学 A5，我们项目 subscription 是 ______，应该用 Key_Shared 因为 ______。
```

面试前把 5 句拼成「我们实践」段落，比背 50 道题更像真人。
