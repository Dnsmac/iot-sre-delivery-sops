# 技术学习框架（可复用模板）

> 从 Pulsar 学习仓库抽象而来。适用于：**消息中间件**（Kafka、MQTT、RabbitMQ）、**协议**（MQTT、CoAP、HTTP/2）、**网络/框架**（Netty、gRPC）等。  
> 用法：复制本节结构 → 填「技术名」→ 按 [落地清单](#落地清单新项目复制顺序) 建仓库。

---

## 一、框架总览

```
                    ┌─────────────────────────┐
                    │  附录：面试题 / 对照表    │  ← 考前/选型用
                    └───────────┬─────────────┘
                                │
┌─────────────┬─────────────────┼─────────────────┬─────────────┐
│  Part A     │  Part B         │  Part C         │  Part D     │
│  面试核心    │  实战开发        │  扩展/运维       │  问题百科    │
│  P1         │  P2              │  P3             │  全阶段索引  │
└─────────────┴─────────────────┴─────────────────┴─────────────┘
         │              │                │
         │              ├─ 写代码         │
         │              ├─ 排障          │
         │              ├─ 性能调优       │
         │              └─ 环境差异       │
         │
         └─ STUDY-TRACKER（日程 + 毕业标准 + 每日日志）
         
实战项目层（Part E / projects/）← 综合演练，不压缩知识体系
设计 Spec → 实施 Plan → 仓库落地（Superpowers 可选）
```

### 三条铁律（任何技术都适用）

| 铁律 | 含义 |
|------|------|
| **优先级显式** | 先定 P1/P2/P3（如：面试 > 开发 > 运维），目录和日程都按权重来 |
| **开发 = 写 + 排 + 调** | P2 必须含：API/用法、解决问题、性能调优（含影响排序），不能只有 API 清单 |
| **毕业即归档** | 每块有「毕业考」；过了不必每天重读，只保留索引和字典附录 |

## 二、优先级怎么定（P1 / P2 / P3）

开始前用一张表定死，避免学偏：

| 优先级 | 典型内容 | 你怎么定 |
|--------|----------|----------|
| **P1 面试/原理** | 是什么、架构图、核心概念、与竞品对比、高频题 | 要面试 → P1；仅工作中用 → 可降为 P2 |
| **P2 开发** | 客户端 API、多服务规范、排障、调优金字塔、环境差异、推动改造 | **默认必有** |
| **P3 扩展** | 集群部署、监控、安全、源码、压测、高级特性 | 有余力 / 要上线运维 |

**示例（可自行改）：**

| 技术 | 建议 P1 | 建议 P2 | 建议 P3 |
|------|---------|---------|---------|
| Kafka | 架构、ISR、消费组、Exactly-once | Producer/Consumer 调优、排障 | KRaft、MirrorMaker、运维 |
| MQTT | QoS、Retain、主题层级、Broker 架构 | 客户端、会话、遗嘱 | EMQX 集群、桥接 |
| CoAP | 报文、Observe、CON/NON | 客户端/服务端实现 | 低功耗网络、NB-IoT 场景 |
| Netty | 线程模型、Pipeline、零拷贝 | Bootstrap、编解码、背压 | 内存泄漏排查、生产参数 |

## 三、Part A ~ D 写什么（通用提纲）

### Part A：面试核心（P1）

> 目标：能讲清原理、画图、对比、答高频题。

**每章固定结构（复制到每个 A*.md）：**

```markdown
# A{n} 标题
> 优先级: P1 | 面试

## 面试常问
## 核心知识（图/表）
## 必答要点
## 易错点
## 相关章节 → Part B / Part D / 附录
```

**建议章节骨架（按技术裁剪）：**

| 章节 | 通用主题 | Kafka 例 | MQTT 例 | Netty 例 |
|------|----------|----------|---------|----------|
| A1 | 是什么、为什么、选型 | vs Pulsar/RocketMQ | vs HTTP/WebSocket | vs Tomcat |
| A2 | 架构、核心组件、数据路径 | Broker/ZK/分区 | Broker/主题/QoS | Reactor/Boss-Worker |
| A3 | 逻辑模型/命名空间 | Topic/Partition | Topic/层级 | Channel/Pipeline |
| A4 | 核心对象/消息模型 | Record/Offset | Publish/Packet | ByteBuf/Event |
| A5 | 消费/订阅/会话语义 | Consumer Group | Clean Session/QoS | EventLoop 绑定 |
| A6 | 可靠性/ACK/投递语义 | acks/isr | QoS 0/1/2 | flush/consolidate |
| A7 | 保留/过期/清理 | retention | retain/遗嘱 | — |
| A8 | 异常/重试/DLQ | — | — | 异常传播 |
| A9 | Schema/序列化 | Schema Registry | Payload 格式 | 编解码器 |
| A10 | 高级特性 | 事务/压缩 | 桥接/共享订阅 | 原生传输 |
| A11 | 存储/底层（若有） | Log Segment | — | 内存池 |
| A12 | 性能与规模 | 分区/批量 | 连接数 | 线程/内存 |

**附录 A：** 50+ 面试题索引（题 → 章节 → 3 句要点）  
**附录 B：** 与最接近竞品/替代方案的对照表

---

### Part B：实战开发（P2）

> 目标：能写代码、排障、调性能、说清环境差异、必要时推动团队改策略。

**Part B 固定子结构（不要拆散）：**

```
B1~B8   写代码（Client API、规范、本地环境、框架集成、配置）
B9      开发中解决问题（方法论 + N 个场景手册）
B10     性能调优（金字塔 + 决策树 + 参数表）
B11     性能验证（指标、埋点、自测）
B12     环境模型（单机/集群/K8s/嵌入式 — 按技术裁剪）
B13     推动策略改造（何时不改、话术、证据、分期）← 有团队现状时必做
```

**B10 调优金字塔（通用，填技术名即可）：**

```
L0 架构/模型选择（Topic 设计、QoS、线程模型）  ★★★★★
L1 批量/合并/压缩（或 Netty 的 write buffer）    ★★★★★
L2 并发度（分区、连接、EventLoop、worker 数）   ★★★★
L3 客户端/库参数微调                            ★★★
L4 服务端/中间件配置                            ★★
L5 基础设施（磁盘、网络、CPU）                  ★★
```

**B9 场景手册（每技术至少 8~12 个）：**

| 类型 | 通用场景 |
|------|----------|
| 功能 | 发了收不到、重复、乱序、积压 |
| 性能 | 吞吐不够、延迟高、OOM |
| 环境 | 本地 OK 生产不行 |
| 特化 | Kafka rebalance / MQTT 会话踢下线 / Netty 泄漏 |

**附录 C~F（开发字典，不必毕业）：** API 速查、性能参数、排查决策树、命令/工具速查  
**附录 I/J：** 环境迁移 Checklist、环境差异矩阵  
**附录 K：** 方案一页纸（推动改技术选型或架构时用）

## 四、STUDY-TRACKER 模板（进度把控）

每个技术仓库放一份 `docs/STUDY-TRACKER.md`，包含：

1. **模块状态表** — `未学 | 已学 | 已毕业`
2. **6 周日程** — 每天「当天过关标志」
3. **毕业考** — Part A / B写代码 / B排障调优 / B推动改造
4. **最低够用线** — 时间紧时的最短路径
5. **每日日志** — 过关 / 未过关 / 状态变更
6. **收工规则** — 同一标准 2 天不过不开新章

**「不用再看了」四标准（至少满足 3 条）：** 能讲、能用、能判、能排。

## 七、不同技术类型的裁剪建议

### 消息中间件（Kafka、Pulsar、RocketMQ）

- Part A 全保留；强调订阅语义、保留策略、对比表  
- Part B 必须有 B9/B10/B12/B13  
- Part C 压测、集群、监控必做  
- 项目 P4：消费模式/分区策略迁移  

### 协议（MQTT、CoAP、AMQP）

- Part A 加重：**报文/ QoS / 会话 / 与 HTTP 对比**  
- Part B 加重：**报文调试工具**（mosquitto_pub、libcoap）、**弱网/低功耗**注意点  
- B12：嵌入式 vs 云端 Broker vs 边缘网关  
- 示例：最小客户端/服务端各一个  
- 压测：连接数 + 消息大小 + QoS 组合  

### 库/框架（Netty、gRPC）

- Part A 加重：**线程模型、内存、生命周期**（面试高频）  
- Part B 加重：**内存泄漏排查、Pipeline 设计、背压**  
- Part C：生产 JVM 参数、堆外内存、火焰图  
- 示例：Echo、HTTP 拆包粘包、自定义协议  
- 问题百科：泄漏、断连、慢 Handler  

### 纯理论/规范（如 CoAP RFC 深读）

- Part A 可占 70%；Part B 偏「实现 checklist」  
- 示例用 C/Java 最小实现各 1 个
