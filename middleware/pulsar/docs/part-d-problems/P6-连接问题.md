# P6 连接断开 / 无法连接

> 优先级: **P2 排障** | 深度：批次 3 ✓  
> 链接: [B9 排障](../part-b-java-dev/B9-排障手册.md) | [P9](P9-本地与集群差异.md)

---

## 典型现象

- `org.apache.pulsar.client.api.PulsarClientException: ... Not connected`
- `Connection refused` / `Name resolution failed`
- 运行一段时间后批量断连、自动恢复。
- K8s 内 Pod 能 ping 不能连 **6650/8080**。

---

## 原因（按概率排序）

| # | 原因 | 说明 |
|---|------|------|
| 1 | **serviceUrl 错误** | `pulsar://` vs `pulsar+ssl://`，主机名、端口 |
| 2 | **Broker 未就绪 / 重启** | 客户端会重连，需重试逻辑 |
| 3 | **防火墙 / 安全组** | 6650 binary、8080 HTTP 未放行 |
| 4 | **K8s Service 类型** | 集群内用 headless/clusterIP，外部用 LB |
| 5 | **TLS 配置不一致** | 一端 SSL 一端明文 |
| 6 | **连接数过多** | Broker `maxConnections`、文件描述符 |
| 7 | **负载均衡 / 代理超时** | Nginx idle timeout 断开长连接 |
| 8 | **版本不兼容** | 客户端与 Broker 版本差过大 |

---

## 排查步骤

### 1. 最小连通性

```powershell
Test-NetConnection -ComputerName localhost -Port 6650
curl http://localhost:8080/admin/v2/brokers/healthcheck
```

### 2. 核对 serviceUrl

```java
// 本地 Standalone
.serviceUrl("pulsar://127.0.0.1:6650")
// 集群：是否 advertisedAddress 与客户端可见主机一致
```

### 3. Broker 日志

```powershell
docker logs pulsar-standalone 2>&1 | Select-String -Pattern "error|refused|auth"
```

### 4. 认证

- 若开启 JWT：`authentication` + `authorization` 配置是否传入 token
- 401/403 与网络错误区分

### 5. 客户端重连

Pulsar Java Client **默认自动重连**；检查是否在断连期间 `send` 未重试导致业务失败。

```java
PulsarClient.builder()
    .serviceUrl(url)
    .connectionTimeout(30, TimeUnit.SECONDS)
    .operationTimeout(30, TimeUnit.SECONDS)
    .build();
```

### 6. K8s 专项

见 [P10](P10-K8s问题.md)：DNS、Service、Probe 是否误杀 Pod。

---

## 解决方案

| 场景 | 措施 |
|------|------|
| 开发 | `scripts/standalone-up.ps1`，确认 6650/8080 |
| 生产 | 固定 advertisedAddress；客户端用稳定 LB 地址 |
| TLS | 统一 `pulsar+ssl://`，信任链配置到 JVM |
| 长连接 | 调大 LB idle timeout；或客户端 keep-alive |
| 连接风暴 | 连接池化、合并 Client 实例（一个进程一个 Client） |

---

## 易错点

- 每个消息 new 一个 `PulsarClient` → 连接爆炸。
- Docker 内用 `localhost` 指代错误容器。

---

## 面试一句话

> 连不上先测 6650 和 8080 健康检查，再对 serviceUrl 和 advertisedAddress；Java Client 会自动重连，业务要在发送失败时重试，K8s 里常见是 Service/DNS/TLS 配错。
