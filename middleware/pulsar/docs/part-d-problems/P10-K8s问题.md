# P10 Kubernetes 部署问题

> 优先级: **P2/P3 运维** | 深度：批次 3 ✓  
> 链接: [P6 连接](P6-连接问题.md) | [P9](P9-本地与集群差异.md) | Part C

---

## 典型现象

- Pod **Running** 但应用连不上 Pulsar。
- Broker Pod 频繁 **CrashLoopBackOff**。
- Helm 安装后 **ZooKeeper 起不来**。
- 集群内 Consumer 正常，集群外不行（或反之）。
- 滚动升级后 **短暂全断**。

---

## 原因（按概率排序）

| # | 原因 | 说明 |
|---|------|------|
| 1 | **Service / DNS 错误** | 用了 Pod IP、错误的 headless 名 |
| 2 | **advertisedAddress 不可达** | K8s 内客户端拿到集群外 hostname |
| 3 | **资源 request/limit 过低** | OOMKilled、磁盘 IO 差 |
| 4 | **持久卷未绑定** | Bookie journal/ledger 丢数据 |
| 5 | **Probe 误杀** | liveness 太激进杀 Broker |
| 6 | **单副本升级** | 无 PDB，全挂 |
| 7 | **Init 顺序** | Broker 先于 ZK/Bookie 就绪 |
| 8 | **NetworkPolicy** | 仅允许部分 namespace |
| 9 | **镜像 tag 漂移** | chart 与 manual 配置不一致 |

---

## 排查步骤

### 1. Pod 与事件

```bash
kubectl get pods -n pulsar
kubectl describe pod <broker-pod> -n pulsar
kubectl logs <broker-pod> -n pulsar --tail=200
```

### 2. Service 与端点

```bash
kubectl get svc -n pulsar
kubectl get endpoints -n pulsar
```

确认 `6650`、`8080` 指向正确 Pod。

### 3. 集群内连通

```bash
kubectl run -it --rm debug --image=curlimages/curl --restart=Never -- \
  curl -s http://pulsar-broker:8080/admin/v2/brokers/healthcheck
```

### 4. 配置检查

- `broker.conf` / `conf/pulsar` ConfigMap：`advertisedAddress`、`brokerServiceUrl`
- StatefulSet 的 `volumeClaimTemplates` 是否 Bound

### 5. Helm values

- `initialize`: 是否已 `pulsar-admin` 初始化集群元数据
- `components`: 是否误关 Bookie/ZK

### 6. 升级策略

```bash
kubectl rollout status statefulset/pulsar-broker -n pulsar
```

---

## 解决方案

| 主题 | 建议 |
|------|------|
| 地址 | `advertisedAddress` 用 K8s DNS 名；外部客户端用 Ingress/LB |
| 存储 | Bookie 必须 SSD + 独立 PVC，勿 emptyDir 生产 |
| 资源 | Broker/Bookie 按官方最低线以上；压测后调 |
| 探针 | readiness 通过后再接流量；liveness 放宽 |
| 升级 | 滚动、分区数不变前提下扩缩 |
| 监控 | Prometheus + Grafana Pulsar 模板 |
| 应用 | 同 namespace 用 `pulsar://pulsar-broker:6650` |

---

## 与本地 Docker 差异

| | Docker Compose Standalone | K8s 生产 |
|---|---------------------------|----------|
| 组件 | 单进程 All-in-One | ZK + BK + Broker 分离 |
| 存储 | 本地卷 | PVC + StorageClass |
| 网络 | localhost | Service mesh / Policy |

---

## 面试一句话

> K8s 上 Pulsar 问题多半是 advertised 地址和 Service 不对，其次 PVC 和 OOM；先在集群内 curl healthcheck，再看 Broker 日志和 endpoints，最后才改应用。
