# P4 Backlog 积压

> 优先级: **P1 监控 / P2 排障** | 深度：批次 3 ✓  
> 链接: [A7](../part-a-interview/A7-保留与清理策略.md) | [B3](../part-b-java-dev/B3-消费者.md) | [P5](P5-性能不足.md)

---

## 典型现象

- Grafana/Prometheus 中 **backlog**、**msgBacklog** 持续上升。
- Consumer lag 越来越大，实时性变差。
- 磁盘使用率上升，Broker/Bookie 告警。
- 生产者开始变慢或报错（Backlog Quota 背压）。

---

## 原因（按概率排序）

| # | 原因 | 说明 |
|---|------|------|
| 1 | **消费速度慢于生产** | 下游 DB、RPC、CPU 瓶颈 |
| 2 | **Consumer 实例不足** | 分区/Key 并行度未吃满 |
| 3 | **Consumer 挂掉或反复 rebalance** | 有效消费力下降 |
| 4 | **单条处理过重** | 同步 IO、大消息反序列化 |
| 5 | **热点 Key** | Key_Shared 下少数 Key 打满一个 Consumer |
| 6 | **receiverQueueSize 过大** | 内存占满、GC 导致更慢（次要） |
| 7 | **Backlog Quota 触发 hold** | 表现为生产端阻塞，根因仍是消费慢 |

---

## 排查步骤

### 1. topics stats

```powershell
docker exec pulsar-standalone bin/pulsar-admin topics stats persistent://dev/test/events
```

关注：

- `subscriptions.<name>.msgBacklog`
- `subscriptions.<name>.msgRateOut` vs Topic `msgRateIn`
- `subscriptions.<name>.consumers` 数量与 `connected`
- `subscriptions.<name>.type`（Shared/Key_Shared）

### 2. 定位慢在哪

| 信号 | 推断 |
|------|------|
| msgRateOut ≈ 0 | Consumer 未连或卡死 |
| msgRateOut > 0 但 < msgRateIn | 处理能力不足 |
| 某 Consumer backlog 特别高 | Key 热点或分配不均 |

### 3. JVM / 应用

- 线程 dump：是否阻塞在外部调用
- GC 日志：是否 Full GC 频繁（见 [P8](P8-内存溢出.md)）

### 4. 集群资源

```powershell
docker exec pulsar-standalone bin/pulsar-admin brokers healthcheck
# Bookie 磁盘、ensemble 写延迟
```

### 5. Namespace 策略

```powershell
docker exec pulsar-standalone bin/pulsar-admin namespaces get-backlog-quotas persistent://dev/test
```

## 解决方案

| 层级 | 措施 |
|------|------|
| 扩容 Consumer | 增加实例；**分区数 ≥ Consumer 数**（分区 Topic） |
| 优化处理 | 批量写库、异步 IO、减小消息体 |
| 拆分 Topic | 按业务线拆分，避免单 Topic 热点 |
| 热点 Key | 业务拆分 Key、salt、或单独队列 |
| 临时止血 | 限流生产、扩容 Bookie 磁盘 |
| 策略 | `producer_request_hold` 背压优于 `consumer_backlog_eviction` 丢消息 |
| 监控告警 | backlog > 阈值、msgRateOut/msgRateIn < 0.8 |

**10W 设备压测（C11）：** 提前定分区数、Consumer 数、Key 分布，见项目 `projects/`。

---

## 预防

- 压测时记录「单 Consumer 吞吐」和「端到端延迟」基线。
- Retention 足够长，避免积压未消 Retention 先删数据（见 [P1](P1-消息丢失.md)）。

---

## 面试一句话

> Backlog 就是消费跟不上生产；先看 stats 里 msgRateIn 和 msgRateOut、Consumer 是否 connected，再扩 Consumer 或优化处理；Shared 非分区下扩实例有效，Key_Shared 还要看 Key 是否热点。
