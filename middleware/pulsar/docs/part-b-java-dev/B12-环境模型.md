# B12 环境模型与差异

> 优先级: **P2 开发** | 预计阅读 35 分钟 | 深度：批次 4 ✓

## 本章解决什么问题

弄清 **Standalone / Cluster / K8s** 三种部署差异、dev/压测/prod 配置矩阵、哪些验证能在本地做、哪些必须上集群，以及上线迁移要看什么。

---

## 一、三种部署形态

| 形态 | 组件 | 典型用途 | 连接方式 |
|------|------|----------|----------|
| **Standalone** | 单进程 All-in-One | 本地开发、功能学习 | `pulsar://localhost:6650` |
| **Cluster** | ZK/Oxia + 多 Broker + 多 Bookie | 压测、生产 | Broker 列表或 Proxy |
| **K8s/Helm** | Cluster 的容器化 | 生产主流 | Service DNS / Ingress |

```
开发笔记本 → Standalone (Docker)
压测机房   → Cluster（与生产同拓扑缩小版）
生产       → K8s + 监控 + TLS + RBAC
```

---

## 二、dev / 压测 / prod 配置矩阵

| 维度 | 开发 | 压测 | 生产 |
|------|------|------|------|
| Tenant | `dev` | `company-stress` | `company` |
| Auto-Create | 可开（学习） | **关** | **关** |
| Batching | 可关便于 debug | **与 prod 一致** | 开 + 压缩 |
| TLS | 无 | 建议开 | **必须** |
| 分区/订阅 | 随意 | **与 prod 一致** | Key_Shared + 分区 |
| 数据 | 可 truncate | 隔离 | Retention 合规 |

---

## 三、Standalone 能 / 不能

| ✅ 能 | ❌ 不能 |
|------|--------|
| Java API、ACK、DLQ、Schema | 真实峰值 QPS、10W 连接 |
| Admin 命令、排障思维训练 | 多 Broker Bundle 均衡 |
| examples / 单元测试 | 作为容量评估依据 |
| Batching **趋势**对比 | Bookie 集群故障演练 |

---

## 四、K8s 常见坑

| 坑 | 后果 | 规避 |
|----|------|------|
| advertisedAddress 不可达 | 客户端连不上 | 用集群内 DNS |
| liveness 杀长消费 Pod | 反复 rebalance | 调 probe / 独立消费部署 |
| memory limit < JVM heap | OOMKilled | limit ≥ heap + 直接内存 |
| ConfigMap 变更未滚动 | 旧配置 | 滚动重启 |
| 无 PVC | Bookie 丢数据 | StatefulSet + SSD |

详见 [P10](../part-d-problems/P10-K8s问题.md)、[C1](../part-c-ops/C1-集群部署.md)。

## 五、环境 × 调优动作

| 动作 | Standalone | Cluster |
|------|-----------|---------|
| API 功能验证 | ✅ | ✅ |
| Batching on/off 对比 | 趋势 | **准确** |
| 连接数 / 10W 模拟 | ❌ | ✅ |
| DLQ / Retry 验证 | ✅ | ✅ |
| Tiered / Geo | 有限 | ✅ |
| 性能签字 | ❌ | ✅ |

## 七、易错点

1. 本地 OK 直接上 prod 配置（[P9](../part-d-problems/P9-本地与集群差异.md)）。
2. 压测环境 batch 关、生产开，结果不可比。
3. 在 Standalone 签 10W 设备 SLA。
4. K8s 用 localhost 连 Broker。
