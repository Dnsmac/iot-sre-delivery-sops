# B9 开发中解决问题

> 优先级: **P2 开发** | 预计阅读 45 分钟 | 深度：批次 1

## 五步方法论

```
1. 确认现象     丢了？重复？慢？积压？断连？（用户描述 often 不准，要数据）
2. 划界         Producer 侧 / Broker / Consumer 侧 / 配置 / 环境
3. 拿证据       stats、peek、日志、metrics、thread dump
4. 缩小范围     单 Topic？单订阅？全局？发布后才出现？
5. 验证修复     改一个变量，对比 stats 前后
```

## 诊断工具箱

| 工具 | 命令/方式 | 看什么 |

## 场景 1：消息发送了，Consumer 没收到

**现象：** Producer 无异常，业务侧收不到。

**定位链：**

```
Producer sendAsync 有 exceptionally 吗？
  → stats 里 msgRateIn 增加了吗？
    → 否：没进 Broker（Topic 错、权限、发送失败）
    → 是：看 Consumer subscriptionName 是否一致、是否连对集群
      → backlog 增加但 Consumer 没日志？Consumer 挂了或没订阅
      → msgRateOut 为 0？订阅模式/过滤问题
      → TTL 删了？看 retention/TTL
```

**Java 检查：**

```java
producer.sendAsync(msg).exceptionally(ex -> {
    log.error("send failed", ex);
    return null;
});
```

**示例：** [MissingAckDemo](../../examples/java/pulsar-troubleshooting/src/main/java/com/demo/pulsar/trouble/MissingAckDemo.java)

## 场景 2：重复消费

**现象：** 同一条业务数据执行两次。

**原因（概率序）：** ackTimeout 过短 > 崩溃重启 > NACK > Shared rebalance > 累积 ACK 批量重投。

**解决：**

```java
.ackTimeout(60, TimeUnit.SECONDS)  // ≥ P99 处理时间 × 2~3
```

业务表：`INSERT IGNORE` / Redis `SETNX` + messageId。

**示例：** [DuplicateConsumeDemo](../../examples/java/pulsar-troubleshooting/)

## 场景 3：消息乱序

**原因：** Shared；Key_Shared rebalance；多线程发同一 Key；多分区却要全局有序。

**解决：** Key_Shared + STICKY + 同 Key 单线程发送。

---

## 场景 4：Backlog 积压

**看：** `subscriptions[].backlogSize` 持续涨。

**原因：** Consumer 慢（DB/HTTP）、实例不够、分区少、单分区热点。

**解决：** 优化逻辑 → 加 Consumer（Shared/Key_Shared）→ 加分区（提前规划）。

## 场景 6：连接频繁断开

- LB idle timeout < keepAlive
- Broker OOM 重启
- 每请求 new 一个 PulsarClient（应单例）

```java
.keepAliveInterval(30, TimeUnit.SECONDS)
```
