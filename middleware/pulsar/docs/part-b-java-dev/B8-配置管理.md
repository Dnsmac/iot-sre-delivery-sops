# B8 配置管理

> 优先级: **P2 开发** | 预计阅读 25 分钟 | 深度：批次 4 ✓

## 本章解决什么问题

dev / staging / prod **配置分离**、敏感信息注入、Topic 与订阅命名一致，以及关闭 Auto-Create 的落地方式。

---

## 一、推荐配置结构

```yaml
# application.yml（公共）
app:
  pulsar:
    tenant: ${PULSAR_TENANT:dev}
    namespace: ${PULSAR_NAMESPACE:test}

spring:
  pulsar:
    client:
      service-url: ${PULSAR_URL:pulsar://localhost:6650}
```

```yaml
# application-prod.yml
spring:
  pulsar:
    client:
      service-url: pulsar+ssl://pulsar-proxy.company.com:6651
      authentication:
        plugin-class-name: org.apache.pulsar.client.impl.auth.AuthenticationToken
        param:
          token: ${PULSAR_TOKEN}

app:
  pulsar:
    tenant: company
    namespace: production
```

代码中拼 Topic：

```java
String topic = String.format("persistent://%s/%s/order-created",
    props.getTenant(), props.getNamespace());
```

## 二、生产原则清单

| # | 原则 |
|---|------|
| 1 | **关闭 Auto-Create**（`allowAutoTopicCreation=false`） |
| 2 | Topic / Namespace / Retention 由 IaC 或 `pulsar-admin` 预创建 |
| 3 | `subscriptionName` 全环境一致（= 服务名） |
| 4 | Token 仅环境变量 / Secret，不进 Git |
| 5 | 不同环境不同 **tenant** 或 namespace |
| 6 | Schema 来自共享 `events-api` jar |

---

## 三、关闭 Auto-Create（示例）

Broker `broker.conf` 或 Helm values：

```properties
allowAutoTopicCreation=false
allowAutoSubscriptionCreation=false
```

未预创建 Topic 时 Producer 应 **快速失败**，便于发现配置错误，而非悄悄写到 `public/default`。

---

## 四、配置与排障

| 环境 | serviceUrl 常见错误 |
|------|---------------------|
| K8s 内 | 用了集群外 hostname |
| 本地 | Docker 网络 localhost 不通 |
| prod | 忘记 TLS，仍用 pulsar:// |

见 [P9](../part-d-problems/P9-本地与集群差异.md)、[附录 I](../appendices/I-环境迁移清单.md)。

## 六、易错点

1. prod 配置打进 jar 默认 profile。
2. Topic 硬编码 `dev/test` 上线生产。
3. 各环境 subscriptionName 不一致导致重复消费或进度错乱。
4. 只关 Auto-Create 不预建 Topic，上线首日全挂。
