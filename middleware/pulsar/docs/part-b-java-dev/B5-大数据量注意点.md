# B5 大数据量 Java 注意点

> 优先级: **P2 开发** | 预计阅读 30 分钟 | 深度：批次 4 ✓

## 本章解决什么问题

高 QPS、大消息、慢消费、长任务场景下，Java 客户端**参数与代码模式**怎么选，以及与 [B10](B10-性能调优.md)、[P4](../part-d-problems/P4-积压.md) 的衔接。

---

## 一、场景矩阵

| 场景 | 关键配置 / 模式 | 风险 |
|------|-----------------|------|
| 小消息高吞吐 | Batching + LZ4 | P99 延迟上升 |
| 大消息 >1MB | `chunkingEnabled(true)` | Bookie/Broker 限制需对齐 |
| 消费慢 | 扩 Consumer + 加大 `receiverQueueSize` | OOM（见 P8） |
| 长任务 | `ackTimeout` ≥ P99处理×3 | 重复消费 |
| 背压 | `blockIfQueueFull=true` | 线程阻塞需监控 |
| 顺序业务 | Key + Key_Shared + 分区 | Shared 必乱序 |
| 幂等 | messageId / businessKey 去重 | 至少一次语义 |

---

## 二、Producer 侧

```java
client.newProducer()
    .topic(topic)
    .enableBatching(true)
    .batchingMaxPublishDelay(10, TimeUnit.MILLISECONDS)
    .compressionType(CompressionType.LZ4)
    .blockIfQueueFull(true)
    .maxPendingMessages(1000)
    .create();
```

| 参数 | 高吞吐 | 低延迟 |
|------|--------|--------|
| batching | on，delay 5~20ms | off 或 delay 1ms |
| compression | LZ4（>1KB 消息） | 小消息可关 |
| send | async + 失败回调 | sync |

大消息：

```java
.enableChunking(true)  // 客户端分块
```

---

## 三、Consumer 侧

```java
.receiverQueueSize(2000)   // 按 msgSize × count 估内存
.subscriptionType(SubscriptionType.Key_Shared)
.keySharedPolicy(KeySharedPolicy.stickyHashRange())
```

| 现象 | 调整 |
|------|------|
| CPU 低、吞吐低 | 增大 receiverQueue；检查是否 sync 单线程 |
| 内存涨 | 减小 receiverQueue；加快 ACK |
| 重复增多 | 加大 ackTimeout；先写库再 ACK |

---

## 四、线程与 Listener

- **不要**在 Listener 里阻塞 30s RPC；用内部队列 + worker 池，**ACK 在 worker 完成后**。
- **不要**多线程同时 ACK 同一 Consumer 乱序（除非理解并发 ACK 语义）。

---

## 五、对象与 GC

- 避免 `new String(msg.getData())` 在热路径；用 byte[] 或复用 buffer。
- 反序列化用同一 `ObjectReader`（Jackson）单例。
- 监控 JVM GC 与 [P8](../part-d-problems/P8-内存溢出.md)。

---

## 六、10W 级设备（要点）

- Topic：**少量分区** + `key=deviceId`，见 [A12](../part-a-interview/A12-性能与规模.md)、[C11](../part-c-ops/C11-十万设备压测.md)。
- 禁止 10W Topic；禁止 Shared 期望设备有序。

---

## 七、易错点

1. 只调 `receiverQueueSize` 不优化业务 SQL。
2. `blockIfQueueFull=false` 且忽略 `ProducerQueueIsFull`。
3. 大消息不开 chunking 直接 send。
4. ackTimeout 小于正常处理时间 → 假「重复」。
