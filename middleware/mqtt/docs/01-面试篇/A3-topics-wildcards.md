# A3 主题与通配符

> 优先级: **P1 面试** | 预计阅读 25 分钟 | 深度：已深化 | 学习路径：**D2 | 面试：★★★** | 主路径：[学习路径](../学习路径.md)

## 本章解决什么问题

掌握 **主题命名、通配符规则、生产层级规范**，避免 `#` 订阅爆炸和 topic 里塞业务数据。

## 面试常问

1. `+` 和 `#` 区别？发布能用通配符吗？
2. 如何设计 10W 设备的 topic？
3. `$` 开头主题是什么？
4. 主题是否区分大小写？
5. 多租户如何隔离？

## 主题（Topic）本质

- UTF-8 字符串，**层级用 `/` 分隔**，如 `acme/factory/line1/device007/telemetry`。
- **区分大小写**；空格、中文合法但不建议。
- **`$` 开头** 保留给 Broker 系统主题（`$SYS/broker/...`），业务禁用。

Topic **不是文件路径**，是 **路由标签**；Broker 用订阅树匹配。

---

## 通配符（仅订阅侧）

| 符号 | 名称 | 匹配 | 合法位置 |
|------|------|------|----------|
| `+` | 单层通配 | 恰好一层 | 任意层级 |
| `#` | 多层通配 | 剩余所有层 | **必须最后一级** |

示例：

| 过滤器 | 匹配 | 不匹配 |
|--------|------|--------|
| `a/+/c` | `a/b/c` | `a/b/d/c` |
| `a/#` | `a/b`、`a/b/c/d` | `x/a` |
| `#` | 全部（慎用） | — |

**发布：** 禁止使用 `+` `#`，必须具体主题。

---

## 设计规范（生产必守）

```
{tenant}/{product}/{deviceId}/{stream}
```

| 段 | 含义 | 例 |
|----|------|-----|
| tenant | 租户/公司 | acme |
| product | 产品线 | iot |
| deviceId | 设备唯一 ID | device007 |
| stream | 遥测/指令/事件 | telemetry、command |

**下行指令：** 设备 **订阅** `.../command`，平台 **发布** 到该主题。  
**上行遥测：** 设备 **发布** `.../telemetry`，平台 **订阅** `acme/iot/+/telemetry`。

### 反模式

| 反模式 | 问题 |
|--------|------|
| `device/{uuid}/data` 与 `device/data` 混用 | ACL/桥接规则无法统一 |
| 订阅 `#` | 流量爆炸、误收他人数据 |
| 在 topic 里编码 JSON | 应用层应放 payload |

---

## 与「10W 设备」关系

- **不要 10W 个互不相关的顶级 Topic 模式**；应 **统一层级 + deviceId 在 topic 或 payload**。
- 平台侧订阅 `acme/iot/+/telemetry` 即可收全网关上报。
- 若每设备 topic 过长但层级一致，Broker 路由树仍可控；**混乱命名** 才致命。

---

## 生产环境注意点

- 全公司统一 **topic 规范文档**，与 [B4](../02-开发篇/B4-multi-service-conventions.md) 一致。
- ACL 按前缀授权；审计异常 `+`/`#` 订阅。

## 易错点与反例

1. **发布用 `a/+/b`** — 协议不允许，订阅才可用通配符。
2. **`#` 不在最后一级** — 如 `a/#/b` 非法。
3. **混用两套层级** — 桥接和监控失效。
4. **topic 里放 JSON** — 应放 payload。

## 动手验证

```bash
mosquitto_sub -h localhost -t 'acme/iot/+/telemetry' -v
mosquitto_pub -h localhost -t acme/iot/d001/telemetry -m '{"t":1}'
```

## 面试标准答案

### 题：`+` 和 `#` 怎么用？

> 加号匹配单层，井号匹配多层且只能出现在过滤器末尾。发布必须写完整主题不能带通配符。例如 `a/+/c` 匹配 `a/b/c` 不匹配 `a/b/d/c`；`a/#` 匹配 `a` 下所有层级。

### 题：MQTT 主题怎么设计？

> 主题用斜杠分层，发布必须具体，订阅可以用加号表示单层通配、井号表示多层通配但井号只能在末尾。生产上建议固定层级：租户、产品、设备 ID、数据流，这样 ACL、桥接和监控都好做。避免用井号订阅全网，避免把业务数据塞进主题路径。设备和平台约定好上行和下行的主题模板，便于和 Pulsar 等后端通过规则引擎映射。
