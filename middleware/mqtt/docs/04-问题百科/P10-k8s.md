# P10 Kubernetes 部署问题

> 深度：已深化 | Mosquitto 开发 + EMQX 生产

## 现象

- Pod **Running** 但设备 **连不上** 8883。
- 连接 **不稳定**，频繁断开重连。
- 集群内应用能连，**集群外设备** 不行。
- Helm upgrade 后 **部分 Pod 旧配置**。
- Service 有 Endpoint 但 **流量不进**。

## 常见原因

| 原因 | 说明 |
|------|------|
| Service 类型 | ClusterIP 未暴露给外部设备 |
| 未用 LB/Ingress TCP | 设备无法解析 Pod IP |
| 探针误杀 | liveness 查错端口导致重启 |
| 资源 limit | OOMKilled（见 [P5](P5-performance.md)） |
| DNS | 设备连 Pod 名而非 LB 域名 |
| NetworkPolicy | 拒绝 8883/集群总线端口 |
| 证书 Secret 未挂载 | TLS 握手失败 |
| 多副本会话 | 未理解 EMQX 集群会话模型 |

## 排查步骤

1. `kubectl get svc,endpoints -n <mqtt-ns>` 确认 **EXTERNAL-IP/LoadBalancer**。
2. 集群外：`telnet/nc <LB> 8883` 与 `openssl s_client`。
3. `kubectl describe pod` 看 **OOM、探针、事件**。
4. 查 **NetworkPolicy** 与 cloud SG 是否放行。
5. Helm values：**listener、证书、replicaCount** 与 [C1](../03-运维篇/C1-deployment.md) 一致。
6. 集群内 debug：`kubectl run mqtt-test --rm -it --image=eclipse-mosquitto -- pub ...`。

## 解决

- 设备接入用 **LoadBalancer/NodePort+外部 LB** 四层 TCP，非 HTTP Ingress（除非 MQTT over WSS 正确配置）。
- 调整 **liveness/readiness** 为 EMQX 官方推荐路径。
- 设 **PDB、合理 request/limit**（[C2](../03-运维篇/C2-capacity.md)）。
- 集群总线端口 **仅内网**；设备只指 **稳定 DNS**。
- 证书用 **cert-manager** 自动轮换（[C6](../03-运维篇/C6-security-ops.md)）。

## 预防

- GitOps 管理 Helm values；环境分离 namespace。
- 上线 checklist：外网连通性、证书、探针、PDB。
- 杀 Pod 演练（[C8](../03-运维篇/C8-ha-cluster.md)）。
