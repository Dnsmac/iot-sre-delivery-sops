# P4 Consumer Lag 积压

> 优先级: **P1 监控 / P2 排障** | 对齐 [pulsar/P4](../../pulsar/docs/part-d-problems/P4-积压.md)

---

## 典型现象

- **Consumer Lag** 持续上升（Burrow、Kafka Exporter、Cruise Control）。
- 消费延迟变大，下游 DB/API 超时。
- Broker 磁盘涨（retention 长 + 生产快）。
- Producer 阻塞（`max.block.ms`、buffer 满）。

---

## 原因（按概率）

| # | 原因 | 说明 |
|---|------|------|
| 1 | **消费慢于生产** | 下游瓶颈、同步 IO |
| 2 | **Consumer 不足** | 分区数 > 有效 Consumer |
| 3 | **Rebalance 频繁** | 消费停顿 |
| 4 | **单条处理过重** | 大消息、复杂反序列化 |
| 5 | **热点分区** | 某 Key 打满单分区 |
| 6 | **GC / 线程阻塞** | JVM 问题 |

---

## 排查步骤

### 1. 看 Lag

```bash
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group my-service
```

关注：`LAG`、`CURRENT-OFFSET`、`LOG-END-OFFSET`、各 Partition 是否均衡。

### 2. 对比生产消费速率

- Broker JMX / Prometheus：`MessagesInPerSec` vs consumer fetch rate
- 若 out ≈ 0 → Consumer 挂或未连

### 3. 应用侧

- 线程 dump、慢 SQL、外部 RPC
- `max.poll.interval.ms` 过小导致被踢出 Group

### 4. 分区热点

- 某 Partition LAG 远高于其它 → Key 分布不均

---

## 处理手段

| 手段 | 适用 |
|------|------|
| 加 Consumer（≤ 分区数） | 并行不足 |
| 优化消费逻辑 | 单条慢 |
| 增加分区（**仅接受顺序影响时**） | 吞吐上限 |
| 临时扩容下游 | DB/ES 瓶颈 |
| 限流生产 | 保护系统 |

---

## 与 Pulsar 对照口述

| Pulsar | Kafka |
|--------|-------|
| `msgBacklog` | **LAG** |
| `msgRateOut` vs `msgRateIn` | consumer fetch vs producer rate |
| 加 Consumer（Shared/Key_Shared） | 加 CG 内 Consumer（≤ 分区） |

**现网一句：** 我们 Pulsar 看 backlog；Kafka 岗位问积压我就讲 **lag + 分区并行 + 消费端瓶颈**，思路一样。
